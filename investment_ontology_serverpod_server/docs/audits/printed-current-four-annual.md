# 실제 현재열 표기 4개 기준의 원문 고정 복구 후보

기준 커밋 35894239의 189개 캐시와 별도로 4개 기준을 추가했다. 일반 파서 문법을 넓히지 않는다. 프로필은 법인코드·현재 회사명·접수·연간기간·연결/별도·표지와 실제 숫자 원문의 URL 및 SHA를 모두 고정한다. 공식 shell은 기존 캐시 fetcher가 같은 법인코드와 접수의 좌표로 검증한다. 저장 Source는 숫자 원접수를 그대로 쓴다.

| 법인 | 접수·기간 | 기준 |
|---|---|---|
| 유진테크놀로지 01085026 | 20230331004027, 2022.01.01~12.31 | 연결·별도 |
| 다원넥스뷰 01344363 | 20240314000984, 2023.01.01~12.31 | 별도 |
| 아이엠비디엑스 01497373 | 20240401003353, 2023.01.01~12.31 | 별도 |

원문 현재열은 `제13당기`/`제13기당기`, `제15기당기`, 연도와 별도 기수행으로 인쇄되었다. 시작일과 종료일은 CIS·CE·CF에 실제 인쇄되어 있다. 따라서 ContentsOn의 말일-only 사례와 달리 `flowCaptionPrintedStart:true`를 보존한다. 기수나 날짜를 새로 만들어 원문에 쓰지 않는다.

실제 7개 직접 셀(자산·부채·자본·매출·영업손익·전체 순손익·영업활동 현금흐름)을 현재열 위치와 원래 계정명 그대로 반환한다. 원 단위는 BS/CIS/CE/CF 각각 직접 인쇄되어 있다. CE 해당 연도 1월 1일·12월 31일 사이의 전체 순손익과 기말 자본을 CIS·BS에 대조하고, CE 기초 자본은 BS 전기 자본과 대조한다. CF 영업·투자·재무·환율과 원문 순증감의 산식, 기초→기말 현금, BS 전기/현재 현금이 모두 일치해야 한다. 원문 전체 SHA와 각 행·셀 위치도 일치해야 한다. 부모/NCI 값을 전체 값으로 대체하지 않는다.

이는 **부분 핵심 7계정 복구**이며 전체 재무제표 복구가 아니다. 유형자산 취득과 나머지 계정은 이 프로필에서 수집하지 않는다. 비교값도 새로 수집하지 않는다. 유진 연결의 전전기 손익표에 2년 범위가 인쇄된 사실을 현재기간의 검증으로 확장하지 않는다. nullable XBRL ID와 실제 계정명·원 단위·원래 숫자 셀·period/provenance를 유지한다.

고정 registry 방식의 publicAttempt=3 이후 1회 캐시 재검증을 사용한다. 기존 API/noData 증거와 attempts, 반대 기준 보고서·Source·숫자 및 재실행 감사의 멱등성을 그대로 보존한다. 일반 재시도 한도나 큐 우선순위는 변경하지 않았다.

실제 원문 양성, 단위/독립 CE 날짜/숫자/법인/이름/기간/좌표/접수/기준/표지 변조 음성, 현재 7계정 화면 매핑 및 기존 ContentsOn 회귀를 순수 테스트로 확인한다. 기존 registry 통합 회귀에는 새 4개 정상 큐·cap3 캐시·반대 기준 불변·API0·실제 7셀·summary/SQL·출처의 printedStart 확인을 작성했다. **루트가 DB 슬롯을 사용 중이므로 DB 회귀는 작성만 했고 실행하지 않았다.** 운영 변경도 없다.
