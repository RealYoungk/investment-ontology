## 원문과 실행 범위

각 항목은 서버 assets/financial_source_cache 안에 공식 shell·표지·요청한 연결 또는 별도 절 전체 raw 바이트를 보존한다. Gaia/Pandora와 Innovex/씨알푸드의 fixture에 빠진 shell은 이전 읽기 전용 감사의 실제 공식 raw를 재사용했고 새 GET은0이다. compiled registry가 manifest SHA를 고정하며 manifest 안에는 법인/접수/사업연도/구분/시작·끝날짜/공식 URL/각 raw SHA/규칙 버전이 있다. 실제 표지의 연간기간·회사·정기보고서 종류와 shell의 고유 법인·접수·문서 노드, 원문 전체 계정·단위·현재열·등식을 기존 strict fetcher/parser로 다시 검증한다. caller가 임의 package나 검증 flag를 넣는 경로는 없다.

패키지마다 세 개의 고정 URI만 응답하는 네트워크 없는 어댑터를 사용한다. 다른 URL·노드·부족한 원문·SHA 변경·알 수 없는 manifest·다른 기간/법인/구분은 거부한다. runtime `.gitattributes`의 -text로 checkout 시 CRLF/공백/JSON 바이트를 변환하지 않는다. 기존 Docker assets 복사로 패키징하며 test fixture나 공개 DTO는 runtime 패키지에 넣지 않는다.

기존 admin 정상 재무 job 안에서만 수행한다. authoritative financial_scope의 최신 같은 기간 접수·연간5개년·상장 법인 연결을 트랜잭션 안에서 재확인한다. basis별 manifest digest+접수+basis+rule version global advisory lock과 filing row lock을 사용한다. 성공·원문검증 실패 각각 한 번 Source audit를 남기고, 취소·이미 처리된 package·최신정정에 밀린 접수는 새 기록을 하지 않는다. 기존 보고서·숫자·정상 출처 audit와 충돌하면 거부한다. 동일 트랜잭션에서 정상 _store 및 정상 연간 audit 또는 기존 typed absence 저장을 사용한다. 임의 DB 쓰기나 새로운 endpoint/model/migration은 없다.

숫자 정상 저장만 job.updated에 더한다. 명시적 비적용은 숫자0건으로 기록하고 별도 source-bound noData이다. 빈 파싱/실패/비어 있는 계정을 0이나 비적용으로 취급하지 않는다. null XBRL 계정 ID, 인쇄 명칭·단위·원화 직접값·현재기간·원접수·원문 URI/SHA·행 provenance를 보존하며 전체 재무제표 복구라고 표시하지 않는다.

한 실행의 캐시 구분별 처리와 일반 연간 공개 큐는 합계 최대10개다. 같은 접수의 연결·별도도 각각 이 제한을 소비하므로 10기간 상한보다 보수적이다. 연속실패6, 공개attempt3 및 일반attempt/일일 meter를 바꾸지 않는다. 남은 고정 package는 별도 cached.remaining으로 숨기지 않는다. 실제 숫자 저장 또는 실제 처리 무실패 진전이 있으면 기존 예약 경로에서30초, 실패만/무진전은15분 이후 예약한다. 예약은 실행 종료 당시 시각이며 한 번의 가장 이른 예약을 유지한다. 실패 audit가 있는 package는 다시 고르지 않으므로 무한 재시도가 아니다.

## 검증 범위

17개 실제 패키지 모두 정상 fetcher/parser 검증 및 manifest/raw SHA 확인. 모든 entry에 대해 법인·접수·연도·정기종류·월·구분·already stored/source-verified noData·공개cap2/4·manifest/raw 변조 거부 단위가 있다. 인가 범위와 숫자 source guard를 완화하지 않았다.

격리 normaljob은17개 양성, RootlocOFS/ElivisionCFS의 SHA실패·취소·최신정정 제외6개, batch 최대10/실패6·잔여/재개2개를 검증한다. Elivision/Talos/PIM 기존 반대 구분은 이미 저장된 공개 report/source/facts DTO를 재사용해 격리 ID만 새로 부여하고 전후 불변을 비교한다. 나머지 반대 구분은 명시한 합성 보존 sentinel이며 비공개 운영 DB 전체 원형 검증이라고 주장하지 않는다. 숫자 결과의 공식 Source SHA/URI/null ID/current 핵심계정과 요약값, audit 구분·카운터·재실행 저장0·job.updated를 확인한다. 기존 Talos/PIM 9개 회귀도 유지한다.

운영 DB·counter reset·외부 원문 GET·DART API 호출·배포는 하지 않는다. 이번 후보는 고정 검증자료만 지원하며 전체 미완료 회사의 일반 원문 확보나 모든 과거 자료의 완료를 뜻하지 않는다.
