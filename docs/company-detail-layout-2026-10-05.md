# 기업 상세 레이아웃 정리

shad 0.99.4 및 기존 서비스 토큰을 유지하고 기업 상세의 공통 헤더, 개요 배치를 수정했다. 데이터와 계산식, 출처, 인증은 변경하지 않았다. 운영 배포는 수행하지 않았다.

- 시장 배지·종목코드·업종을 기업명 위에 배치했다. 이름과 액션은 모바일에서 행을 나눠 긴 이름이 버튼과 경쟁하지 않도록 했다.
- 핵심 지표를 DataPanel(ShadCard)에 묶고 숫자 크기, 열 간격, 행 간격을 정리했다. 넓은 화면 6열, 중간 화면 3열, 모바일 2열이며 결측 사유·기준 기간·업종 중앙값은 보존했다. 전체 지표와 계산식 열기는 유지했다.
- 개요의 본문은 1100px 이상에서 사업 정보 7 : 보조 정보 4 비율로 나눴다. 사업·매출·사업지표를 왼쪽, 주가·뉴스·시장환경·정관을 오른쪽에 배치했다. 더 좁은 화면은 순서대로 한 열로 보여준다. 다른 탭은 공통 헤더를 적용하고 기존 내용·상호작용을 유지한다.
- 기본 Shad 위젯 또는 기존 서비스 컴포넌트를 사용했으며 새 기본 위젯 래퍼와 vendor 수정은 없다.

검증: 변경 파일 analyze 오류 없음, 관련 Flutter 테스트 17개 통과, 상단 반응형 테스트를 320/390/768/1045/1440px로 확장한 별도 7개 통과(기존 테스트 일부 중복). Flutter Web release 빌드 88.5초에 통과. git diff --check 통과.

실제 최종 빌드를 기존 허용 개발 origin http://127.0.0.1:8110에서 임시 정적 프리뷰로 열었다. 아크릴 공개 데이터 로딩, 1280px 두 열 배치, 지표 클릭→계산식 시트→닫기, 390px 한 열 배치와 재무 탭의 차트 데이터를 확인했다. 인증을 우회하지 않았다. 원래 사용자 운영 탭은 보존했고 임시 탭·프리뷰 프로세스와 viewport override를 정리했다.

화면: outputs/design/company-detail-2026-10-05/desktop.jpg, mobile.jpg.

개발 앱의 기존 incremental compiler는 중간 radiusSm 오류 뒤 app_auth summary 캐시 오류를 반복해 이전 화면을 제공했다. radiusSm 소스 오류는 수정하고 분석·테스트·release 빌드로 확인했다. Serverpod MCP hot_restart 성공 응답에도 개발 앱 캐시는 복구되지 않아 실제 시각 검증은 최종 release 프리뷰를 기준으로 했다. 개발 앱의 캐시 정상화나 운영 배포 완료로 표현하지 않는다. 모든 상세 탭/기업/OS 접근성을 전수 검증한 것은 아니다.
