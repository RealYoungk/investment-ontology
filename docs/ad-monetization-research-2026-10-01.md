# 알파인더 광고 도입 타당성 검토

기준일: 2026-10-01 (한국). 상태: 조사·가정 계산, 광고 도입 결정 아님.

## 판단

현재는 전면 광고 도입보다 트래픽·비용 측정이 우선이다. 광고는 무료 공개 조회를 유지하는 보조 재원이 될 수 있지만, AI 구독과 본인 인건비까지 회수할 주 수익원이 되는지는 입증되지 않았다. 시행한다면 승인된 비고정 배너 한 자리로 제한한 실험이 가장 단순하다. 직접 스폰서는 통제력이 좋은 비교 후보이나 영업 가능성과 가격은 미검증이다. 보상형은 웹에서도 가능하지만, 현재 무료 데이터를 잠그는 Offerwall은 서비스 방침과 충돌하고, 가치 있는 추가 보상 기능도 아직 검증되지 않아 보류를 권한다.

이 문서의 추천·실험 기준은 작성자 제안이며 사용자 결정이 아니다. 광고 신청·광고주 연락·추적 설치·배포는 하지 않았다.

## 1. 확인된 사업 상태와 미확인 값

- 사용자: 월 방문자/PV는 아직 모름. 서버비뿐 아니라 AI 구독료, 본인 인건비, 기타 비용을 반영해야 한다고 명시(이번 대화, 2026-10-01).
- 로컬 `docs/iwinv-migration.md`와 `docs/deploy.md`: 서버 기본료 27,720원/월(VAT 포함), 초과 트래픽 별도. 이번 조사에서 청구서를 조회한 것은 아니다.
- 공유 기업 데이터는 공개 조회 유지, 개인 기능에서 가입 유도. 현재 작업 지침과 이관 문서에 명시된 정책이다.
- 점검한 Flutter `lib/`, `web/`, 루트 pubspec에서 gtag/analytics/plausible/posthog 계측 문자열은 찾지 못했다. 외부 대시보드·프록시 로그까지 조사한 것이 아니므로 계측이 전혀 없다고 단정하지 않는다.
- 실제 AI 구독 총액·서비스 배분율·개발/운영 시간·시간가치·결제 수수료·법적 비용·광고 계정 승인·한국 방문자 비중·광고 차단율·단가·유료 전환율은 미확인이다.

## 2. 광고 상품의 정확한 구분

Google Ads는 우리가 광고비를 내고 고객을 데려오는 광고주 상품이다. 웹에 광고를 게재해 수익을 얻는 쪽은 AdSense 또는 Ad Manager다. AdMob은 모바일 앱 대상이며 Flutter를 쓴다는 이유로 Flutter Web에 적용하는 상품이 아니다. [Google 제품 구분](https://support.google.com/adsense/answer/76231), [게시자 상품 비교](https://support.google.com/adsense/answer/9234653?hl=en).

| 방식 | 우리 이익 | 고객 부담 | 도입·운영과 적합성 판단 |
|---|---|---|---|
| AdSense 수동 배너 1개 | 직접 영업 없이 광고 수익, 무료 조회 지원 | 공간·집중력·추가 요청·쿠키 | 사이트 승인 필요. 초기 제한 실험 후보. 단가 보장 없음 |
| AdSense 공식 앵커 | 스크롤 중 가시성 유지 | 화면 점유·닫기 동작, 차트/모바일 입력 간섭 가능 | 공식 형식은 가능하지만 앱과 실제 겹침 검증 필요. 첫 선택으로 권하지 않음 |
| AdSense Offerwall | 반복 방문자의 광고 시청 수익 | 콘텐츠 접근이 끊기고 반복 시청 요구 가능 | 콘텐츠 접근 보상 방식. 현재 공개 조회 정책과 맞지 않음 |
| Ad Manager 맞춤 보상형 | 선택 기능을 쓰려는 사람에게만 광고 노출 | 시청 대기·소리·중단·보상 누락 | 웹 지원. 계정/수요 연결과 보상 기능 개발 필요. 현재는 보류 |
| Kakao AdFit 배너 | 국내 웹 광고 수익화의 비교 후보 | 배너·외부 요청·광고 품질 부담 | 공식 Web 매체 등록 가능. 한국에서 더 잘 번다는 근거는 확보하지 못함 |
| 직접 스폰서 | 광고주·소재·위치·가격 직접 통제 | 협찬이 추천으로 오해될 위험 | 외부 광고 SDK 없는 정적 소재도 가능. 영업·계약·보고·미수금 비용 존재 |
| 제휴 전환 수익 | 적격 가입/구매 등 성과에 따른 수익 가능 | 링크 이동·추천 이해상충 | 금융상품/계좌 제휴는 계약·표시·관련 규정 별도 확인 전 시행 보류 |
| 개인 기능 유료화 | 반복 매출 가능, 광고 노출 없이 고객과 이해관계 정렬 | 결제 비용·무료/유료 구분 | 관심기업 알림·저장한 비교 등 수요 검증 필요. 구현·가격·유료 의사 모두 미검증 |

AdSense는 고유 콘텐츠·정책 준수·HTML 접근 등의 조건을 제시한다. 이번에 읽은 자격 안내는 보편적인 최소 PV 숫자를 제시하지 않는다. 이를 승인 보장으로 해석하지 않는다. [자격 조건](https://support.google.com/adsense/answer/9724?hl=en).

Ad Manager는 유효한 AdSense 계정이 필요하며, 등록 자체가 Ad Exchange 수요 연결 또는 높은 단가를 보장하지 않는다. [계정 등록](https://support.google.com/admanager/answer/7084151?hl=en).

AdFit은 Web URL·카테고리 등록, 광고단위 생성, 스크립트 설치 후 광고 호출을 거쳐 심사한다. 단순히 계정만 만드는 것과 실제 심사 시작은 다르다. 이번에는 신청하지 않았다. [카카오 매체 관리](https://kakaobusiness.gitbook.io/main/partner/adfit/start/media-manage).

## 3. 상단 고정 시안에 대한 정정

기존 시안은 광고 공간만 있는 비활성 Flutter 위젯이다. 실제 광고 배치 적합성은 검증하지 않았고 그대로 광고 코드를 넣으면 안 된다.

AdSense의 직접 구현 sticky 규칙은 폭 300px 이하, 데스크톱 전용 등 조건이 있으며 728×90 고정을 명시적으로 허용하지 않는다. 자체 스크롤에 따른 갑작스러운 광고 숨김 역시 해당 조건과 충돌할 수 있다. 기존 728px 상단 고정/모바일 자동 접기 설계는 AdSense 일반 배너용으로 채택하지 않는다. [공식 Sticky FAQ](https://support.google.com/adsense/answer/10734935?hl=en).

별도로 Google이 제공하는 공식 앵커는 모바일·데스크톱에서 화면 가장자리에 고정되고 닫을 수 있다. 따라서 ‘고정 광고는 모두 불가’도 잘못된 결론이다. 공식 앵커와 임의로 고정한 일반 배너를 구분해야 한다. [공식 앵커](https://support.google.com/adsense/answer/15484692?hl=en).

현재 후보는 (a) 본문과 함께 스크롤되는 일반 배너, (b) 제공업체의 공식 앵커, (c) 직접 스폰서 띠다. 메뉴 안에는 넣지 않고 광고임을 구분한다. 공통 위젯이라는 이유로 로그인·오류·로딩·관리 화면까지 무조건 노출하지 않는다. 메뉴·검색 버튼 근접 배치는 오클릭을 유발할 수 있다. [배치 정책](https://support.google.com/adsense/answer/1346295?hl=en).

## 4. 보상형은 가능한가, 무엇을 보상할 것인가

### 공식 지원

- AdSense Offerwall: 짧은 광고 시청 후 콘텐츠 접근을 부여하는 방식. URL 범위·노출 기준·닫기 횟수 설정이 있다. 한국어를 지원한다. 광고 수요가 없으면 메시지가 나타나지 않을 수 있다. [Offerwall](https://support.google.com/adsense/answer/13865318?hl=en), [보상형 설정](https://support.google.com/adsense/answer/12726063?hl=en).
- Ad Manager: 데스크톱·모바일·태블릿 웹의 자발적 보상형을 지원한다. 영상뿐 아니라 디스플레이 수요도 쓰고, 일부 수요는 소리 확인을 요구한다. 영상 완료/표시 시간 등 완료 조건이 다르므로 ‘항상 30초 영상’으로 약속하면 안 된다. 웹에는 Google 서버 측 보상 검증(SSV)이 없다. [웹 보상형](https://support.google.com/admanager/answer/9116812?hl=en).
- 공식 GPT 예제는 환경 미지원 시 null 반환과 ready/granted/closed 이벤트를 구분한다. 단순 창 닫기나 클릭을 시청 완료로 취급하면 안 된다. [구현 예제](https://developers.google.com/publisher-tag/samples/display-rewarded-ad).

공식 Offerwall 문서 안에 ‘rewarded만 지원’ 문구와 이메일 수집 Beta 절이 공존하고 일부 FAQ는 Ad Manager 기능도 언급한다. 따라서 결제·이메일·맞춤 보상 기능이 우리 AdSense 계정에 모두 있다고 가정하지 않는다. 실제 계정 UI는 미확인이다.

### 보상 제한

Google 보상형은 현금·암호화폐·기프트카드 같은 직접 금전 보상이 금지된다. 보상은 사이트 안에서 본인만 쓰는 양도 불가 혜택이어야 한다. 사전 설명과 명시적 참여, 거절/닫기, 약속한 보상 지급이 필요하다. 일반 배너 클릭에 포인트를 주는 것은 보상형 광고가 아니다. [보상형 정책](https://support.google.com/adsense/answer/9121589?hl=en).

| 보상 아이디어 | 판단 |
|---|---|
| 광고 시청 후 기존 기업 재무/공시 조회 | 공개 데이터 접근을 후퇴시키므로 비추천 |
| 현금·주식·상품권·현금화 포인트 | Google 보상형용으로 채택 불가 |
| 새로 만드는 고급 비교 기능의 24시간 이용권 | 후보. 계정 귀속·양도 불가, 실제 수요가 있어야 함 |
| 광고 없는 이용 시간 | 광고가 충분히 불편해야 성립하는 순환 구조. 초기에는 비추천 |
| AI 보고서 1회 생성 | 호출 원가·오류/지원 비용이 광고 수입을 넘을 수 있음. 현재 요청 중 AI 호출 금지 정책과도 충돌하므로 후보에서 제외 |
| 이미 무료인 기능을 인위적으로 제한해 해제 | 보상 가치보다 불만을 만들 수 있어 비추천 |

자체 보상 서버를 만든다면 계정 인증, 일일 한도, 일회용 요청 식별자, 중복 지급 방지, 만료와 재접속 처리가 필요하다. 클라이언트 이벤트는 Google의 암호학적 서버 검증이 아니므로 고가/금전성 보상의 근거로 쓰지 않는다. 개인 기능 권한은 Serverpod 인증을 통해 부여하고 OntologyAccess 관리자 검사를 우회하지 않는다. 미노출·광고 차단·중도 이탈은 정상 상태로 처리하며 기존 무료 이용은 유지한다.

## 5. 비용: 서버비, 현금비용, 총비용, 추가비용을 구분

다음은 계산을 보여주기 위한 임의 입력이다. 실제 AI 구독료나 사용자 시급을 추정한 것이 아니다.

| 월 비용 항목 | 예시 | 근거/상태 |
|---|---:|---|
| 서버 기본료 | 27,720원 | 로컬 운영 기록. 초과 트래픽 별도, 청구서 미확인 |
| AI 구독 배분액 | 100,000원 | 가정. 여러 프로젝트에 쓰면 총액×이 서비스 사용 비율 |
| 도메인·호스팅·백업 등 | 20,000원 | 가정. 연납은 월 환산 |
| 본인 운영시간 | 300,000원 | 가정: 월 10시간×3만원. 실제 현금 지급은 아님 |
| 신규 광고 개발비 월 배분 | 100,000원 | 가정: 20시간×3만원÷6개월. 견적 아님 |
| 현금비용 소계 | **147,720원** | 본인 노동/개발 배분 제외 |
| 총비용 소계 | **547,720원** | 현금+노동+신규 개발 배분 |
| 총비용 회수 후 30만원을 남길 매출 | **847,720원** | 세금·환전/송금 비용 등 미반영 |

운영시간 10시간 중 광고 관리가 1시간이라고 가정하면, ‘광고를 추가할지’의 비교 비용은 개발 배분 10만원+관리 3만원=월 13만원이다. 기존 서버·AI 비용은 광고가 없어도 드는 한 증분 비용에 다시 포함하지 않는다. 다만 ‘서비스가 사업으로 유지되는지’ 판단에는 전체 배분 비용을 포함한다.

이미 쓴 과거 개발시간은 앞으로 광고를 도입할지 결정할 때 매몰비용과 분리한다. 누적 투자 회수를 목표로 삼으면 별도 회수 기간을 두고 추가한다. 기존 구독으로 개발해 추가 청구가 없더라도 사용자 시간과 구독 배분액이 모두 0이 되는 것은 아니다.

## 6. 매출: PV와 광고 노출은 다르다

기본식은 `실제 광고 노출 수 ÷ 1,000 × 게시자 실수령 기준 eCPM`이다. 여기의 eCPM은 플랫폼 몫 반영 후, 우리 세금·운영비 차감 전 수입으로 정의한다. 광고주 CPM을 그대로 사용하지 않는다. Google의 RPM 정의와 같이 분모를 일관되게 써야 한다. [RPM 정의](https://support.google.com/adsense/answer/190515?hl=en).

`실제 노출 = 월 세션 × 세션당 적법한 광고 기회 × 유효 노출 비율`.
유효 노출 비율은 차단·광고 미충전·기술 실패 등을 합친 가정이며 가시성과 동일하지 않다. 가시성 영향은 관측 단가에 반영될 수 있으므로 임의로 중복 차감하지 않는다. 월 고유 방문자 수, 세션, 앱 경로 조회, 광고 요청, 실제 노출은 서로 다르다.

공통 광고를 유지하고 새로 요청하지 않으면 사용자가 기업 10개를 열어도 광고 노출 10건을 보장하지 않는다. 오래 볼수록 노출이 저절로 증가하지도 않는다. 일반 AdSense에 자동 새로고침으로 수익을 늘리는 구현을 적용하지 않는다. Ad Manager의 별도 갱신 기능/정책과도 혼동하지 않는다. [배치 정책](https://support.google.com/adsense/answer/1346295?hl=en), [GPT SPA 수명주기](https://developers.google.com/publisher-tag/samples/integrations/react).

### 민감도: 아래 단가는 한국 금융 사이트 벤치마크가 아니라 임의 계산값

| 월 실제 광고 노출 | eCPM 1,000원 | eCPM 3,000원 | eCPM 5,000원 |
|---:|---:|---:|---:|
| 10,000 | 10,000원 | 30,000원 | 50,000원 |
| 50,000 | 50,000원 | 150,000원 | 250,000원 |
| 100,000 | 100,000원 | 300,000원 | 500,000원 |
| 300,000 | 300,000원 | 900,000원 | 1,500,000원 |

단가 3,000원·세션당 기회 1회·유효 노출 70%를 가정한 손익분기점:

| 회수 대상 | 필요한 실제 월 노출 | 필요한 월 세션 |
|---|---:|---:|
| 서버 기본료만 27,720원 | 9,240 | 13,200 |
| 현금비용 147,720원 | 49,240 | 70,343 |
| 전체 비용 547,720원 | 182,574 | 260,820 |
| 전체 비용+이익 30만원 | 282,574 | 403,677 |
| 광고 증분 비용 13만원만 | 43,334 | 61,905 |

따라서 ‘월 1만 명이면 된다’고 말할 수 없다. 월 1만 세션, 한 기회, 70% 노출이면 예시 매출은 21,000원이다. 노출·수입이 0일 수도 있다. 지급도 즉시 현금화가 아니다. AdSense USD 지급계정의 일반 지급 기준은 $100이며 계정별 요건이 있다. [지급 기준](https://support.google.com/adsense/answer/1709871?hl=en).

### 보상형은 높은 단가만으로 유리해지지 않는다

임의 예시: 월 1만 세션×기회 1회×참여 10%×실제 표시 70%=700노출.
eCPM을 배너의 5배인 15,000원으로 가정해도 월 매출은 10,500원이다.
보상 획득률 80%라면 560회 지급. 보상 1회 변동원가 20원만 있어도 11,200원으로 매출보다 크다. 단가·참여·원가 모두 가정이며, 이 조합은 보상 원가가 얼마나 중요한지 보여주기 위한 것이다. 노출 기반 eCPM에는 완료율을 매출에 다시 곱하지 않는다. 완료율은 보상 지급 건수와 비용 계산에 쓴다.

### 직접 스폰서/유료의 비교 산식

월 30만원 스폰서 1개가 성사된다면 3,000원 eCPM의 10만 노출과 매출이 같지만, 이는 판매 가능 가격이나 시장 견적이 아니다. 영업/제작/보고 5시간×3만원이면 15만원이 소모된다. 현금 수입만 보고 승리라고 판단하지 않는다.
월 5천원 개인 기능도 가정상 60명이면 30만원 매출이다. 수수료·지원비·개발비·해지율 차감 전이며 유료 수요는 미확인이다. 광고와 유료를 함께 쓸 경우 유료 이용자의 광고 제거와 전환 잠식을 함께 계산한다.

## 7. 고객 영향과 우리에게 되돌아오는 비용

| 고객 영향 | 서비스 손익에 미치는 경로 | 최소화 방안/측정 |
|---|---|---|
| 화면 점유 | 한 번에 보는 재무 행·차트 감소 | 시안 100px는 높이 900px의 11.1%, 76px는 844px의 9.0% 점유(단순 산술). 메뉴 제외 본문 대비는 더 큼 |
| 주의 분산 | 검색→비교→근거 확인 흐름 단절 | 핵심 분석/입력 화면 제외, 실제 과업 성공률·소요시간 측정 |
| 광고 로딩/레이아웃 변화 | 입력 지연, 페이지 이탈 | 여백 예약, 실패 시 복구, 실기기 화면 안정성·입력 지연 측정 |
| 쿠키/외부 요청 | 프라이버시 부담과 동의 UI 추가 | 고지·적용 지역 동의 설정, 개인 메모·관심기업 정보를 광고 타기팅으로 보내지 않기 |
| 투자 광고에 대한 신뢰 혼동 | 서비스가 리딩방/종목을 추천한다는 오해 | 광고 표시, 광고주/카테고리 관리, 문제 광고 신고·차단 운영 |
| 보상 시청 시간/소리 | 즉시 과업 중단, 피로 | 사용자 선택, 사전 조건 설명, 기본 기능 유지, 실패 시 불이익 방지 |
| 보상 누락/중복 | 고객 문의·부정 이용·비용 | 일회 지급·한도·로그·복구; 웹의 검증 한계를 전제로 낮은 원가 보상 |

AdSense는 광고주 URL·카테고리·네트워크·개별 광고 차단 도구를 제공한다. 이것이 모든 부적절한 광고를 사전에 완벽하게 없앤다는 보장은 아니다. [차단 도구](https://support.google.com/adsense/answer/1059482?hl=en).

Google은 쿠키/제3자 광고에 대한 개인정보 고지를 요구한다. EEA·영국·스위스 맞춤 광고에는 인증 CMP 조건도 있다. 한국 사이트라는 이유로 방문자 지역을 무시하지 않는다. 비맞춤 광고도 모든 데이터 처리가 없어지는 뜻은 아니다. 이번 보고서는 한국 개인정보/금융광고 법률 검토 완료를 의미하지 않는다. [필수 고지](https://support.google.com/adsense/answer/1348695?hl=en), [지역별 CMP 조건](https://support.google.com/adsense/answer/13554116?hl=en).

현재 미래 유료 고객의 가치가 미확인이므로 고객 이탈의 금전 손실은 계산하지 않았다. 이후에는 `광고 추가 기여이익 - 잃은 유료 고객 기여이익 - 추가 지원/영업 비용`으로 판단한다. 광고 클릭률 상승이 오클릭이나 피로 때문이면 성공이 아니다.

## 8. Flutter Web 구현 난도

Flutter 공식 문서는 동적 앱 출력이 검색엔진 색인 요구와 잘 맞지 않는다고 설명한다. 이는 광고 승인이 불가능하다는 증거는 아니지만, 실제 광고 크롤러가 콘텐츠를 평가할 수 있는지 별도 확인해야 한다. 필요하면 설명/도움말 같은 공개 HTML 페이지를 보완하되, 자동 콘텐츠 양산을 승인 대책으로 삼지 않는다. [Flutter Web FAQ](https://docs.flutter.dev/platform-integration/web/faq).

배너는 Flutter 색상 박스에 스크립트를 넣는 것으로 끝나지 않는다. 실제 DOM 광고 영역과 크기, 생성/제거 시점, 가림·포커스·포인터 전달을 확인해야 한다. Flutter는 HtmlElementView를 제공하지만 비용이 있을 수 있다. [HtmlElementView](https://api.flutter.dev/flutter/widgets/HtmlElementView-class.html).

특히 앱 내부 스크롤과 브라우저 문서 스크롤은 다를 수 있어 공식 앵커·Offerwall의 노출 트리거/URL 집계가 기대대로 동작하는지 미검증이다. 브라우저 뒤로/앞으로, 탭 이동, 확대, 모바일 키보드, 광고 차단, 빈 응답을 포함해 실기기 테스트해야 한다. 현재 UI 테스트 11개 통과는 이 광고 연동 검증을 대체하지 않는다.

## 9. 권장 실행 순서와 결정 기준

1. **기초 계측과 원가표:** 최소 2주 동안 사람의 세션·기기·국가·핵심 과업 완료·재방문을 파악. 봇/API 호출을 방문자로 세지 않기. 실제 AI 비용 배분과 본인 작업시간을 기입한다. 계측 설치 자체는 이번에 실행하지 않았다.
2. **고객 가치 확인:** 방문자 5~8명에게 기업 탐색 과업을 수행하게 하고 배너/보상형 시안을 비교. ‘광고가 싫은가’ 대신 과업 방해, 기다릴 만한 보상, 지불 의사를 질문한다. 표본은 정성 탐색이며 시장 비율로 일반화하지 않는다.
3. **단순 배너 우선 조건:** 계정 승인·콘텐츠 평가 가능성·배치 적합성이 확인되고 예시가 아닌 실제 단가를 측정할 준비가 되면 일부 공개 화면에만 적용. 첫 단계는 무작위 10% 세션 정도의 노출군과 미노출군을 비교하는 안. 저트래픽이면 작은 차이를 통계적으로 판단하지 못할 수 있다.
4. **가드레일 제안:** 핵심 과업 완료율/7일 재방문이 대조군 대비 5% 이상 상대 하락하면 중단 검토, 광고 관련 오클릭/보상 미지급/콘텐츠 가림은 즉시 중단, 입력 지연 p75가 100ms 이상 악화하면 원인 수정. 이 수치는 업계 표준이 아닌 초기 내부 기준 제안이다. 표본과 신뢰구간 없이 통과를 선언하지 않는다.
5. **경제성:** 확정 수입과 실제 관리시간을 월 환산해 추가 기여이익이 양수인지 먼저 확인. 전체 비용을 회수하지 못해도 보조 수익 실험은 가능하지만 지속 가능한 사업이라고 표현하지 않는다.
6. **보상형/스폰서/유료:** 유용한 저원가 개인 보상과 수요가 확인될 때 보상형 별도 시험. 직접 스폰서는 대상 고객/조회 규모를 설명할 자료를 만든 뒤 판매 가능성 검증. 유료 개인 기능은 인터뷰/가격 실험 후 선택한다.

### 지금 결정할 수 있는 것

- Google Ads를 연결하는 작업은 아니다.
- 기존 상단 고정 시안을 AdSense 배너로 바로 출시하지 않는다.
- 공개 데이터 조회를 광고 시청으로 막는 안은 추천하지 않는다.
- 배너는 보조 수익 후보, 보상형은 보상 가치 검증 후, 스폰서/유료는 비교 대안이다.
- 현재는 광고로 서버·AI·본인 인건비를 회수할 수 있다고 말할 근거가 없다.

## 조사 범위와 한계

기본 웹 검색과 Exa를 병행했고 Google·Flutter·Kakao의 원문을 직접 열어 확인했다. Exa는 3개 검색 묶음에서 15개 검색 결과를 반환했으며, 중복을 제거하고 관련 원문을 검토했다. 검색 결과 수는 독립적으로 검증한 사이트 수가 아니다. 국내 금융 웹 서비스의 실제 광고 단가, 계정별 승인/Offerwall 기능, 광고 수요량은 확보하지 못했다. 광고업체 성공 사례의 수익 상승률은 우리 예측에 사용하지 않았다. Naver 검색 결과 중 광고주용 문서는 게시자 대안 근거로 제외했다. 위 링크들이 본문 근거이며, 동적으로 갱신되는 도움말은 도입 시 재확인한다.
