# 일반 광고와 광고 제거 이용권 — 구현 상태

2026-10-01 · `codex/ad-placement` · 기준 origin/main `0977d2e`.

## 이번에 정한 방향

사용자는 일반 광고로 서비스 운영비를 보태고 광고 제거 유료 BM을 준비하기로 했다.
현재 AdSense 계정은 있지만 alfinder.kr 사이트 승인 전이다(사용자 확인).
가격·결제업체·정기/일회 결제 방식은 아직 정하지 않았다.

## 구현 완료 범위

- 공통 PageFrame 내부의 **홈·시장·기업 목록** 본문 상단에 광고 한 자리.
  기존 고정/자동 숨김 시안은 제거했다. 광고는 페이지와 함께 스크롤된다.
- 기업 상세·재무·관계망·로그인·계정·관리 화면에는 광고 자리를 넣지 않는다.
- AdSense DOM 로더: 최초 한 번 스크립트 로딩, 자동 새로고침 없음,
  빈 광고/차단/타임아웃 시 자리 제거, 해제한 슬롯의 늦은 응답 무시.
- `alfinder.adFree` 서버 발행 스코프가 있는 계정은 AdPlatform 자체를 만들지 않아
  해당 슬롯에서 광고 요청을 하지 않는다. 관리자 권한은 광고 제거와 독립적이다.
- 내 계정에 무료/광고 없는 이용 상태와 유료 옵션 준비 중 안내.
  결제 버튼·가격·구매 완료 흉내는 없다.
- Serverpod `AdFreeAccess.setEnabled`: 서버 내부 관리자 서비스. 익명/일반회원
  호출 차단, DB의 현재 관리자 권한 재확인, 기존 스코프 보존, 세션 폐기.
  브라우저가 구매 성공 플래그를 보내 권한을 받는 공개 API는 없다.

## 아직 없는 것 — 출시 완료 아님

- 실제 게시자 ID/광고단위 ID, 사이트 소유 확인과 승인, 실제 광고 송출.
- 결제·웹훅·영수증·환불·구독 갱신/만료·결제 원장.
- 광고 제공업체와 동의 설정을 반영한 개인정보 처리 고지의 최종 반영.
- 이 워크트리 앱을 실행한 실제 브라우저 QA와 배포.

현 단계 `adFree`는 만료일이 없는 접근 권한 기반이며 유료 구독 시스템이 아니다.
자동 갱신 상품을 판매하기 전에 결제 공급자 ID/이벤트 중복방지·기간·취소·환불 원장을
Serverpod 모델로 구현해야 한다. 클라이언트 결제 완료 URL을 지급 근거로 쓰지 않는다.
권한 변경 시 refresh 토큰을 폐기하므로 재로그인이 필요하다. 아직 유효한 access token과
기존 화면 표시는 즉시 교체되지 않을 수 있다. 실제 유료 전환 UX는 결제 연동 시 완성한다.
어떤 운영 사용자에게도 테스트 광고 제거 권한을 부여하지 않았다.

## 설정

기본은 모두 비활성이다. ID는 공개 식별자이며 비밀 키가 아니다.

| Dart define | 의미 |
|---|---|
| `AD_PLACEMENT_PREVIEW=true` | 빈 광고 시안 표시. 외부 광고 스크립트 요청 없음 |
| `ADSENSE_ENABLED=true` | 광고 요청 허용. ID 둘 다 유효하고 웹일 때만 가능 |
| `ADSENSE_PUBLISHER_ID=ca-pub-…` | 실제 게시자 ID, 숫자 16자리 |
| `ADSENSE_SLOT_ID=…` | 실제 반응형 디스플레이 광고단위 ID, 숫자 10자리 |
| `ADSENSE_TEST_MODE=true` | 기본 true. 테스트 광고 요청용 `data-adtest=on` |

미리보기 플래그가 true이면 실제 요청보다 미리보기가 우선한다.
`testMode`도 Google에 네트워크 요청하는 모드다. 빈 미리보기와 혼동하지 않는다.
빌드 옵션은 `flutter build web --dart-define=…` 또는 사용자가 실행하는
Serverpod flutter_apps 설정의 `dart-define`으로 전달한다.

계정별 광고 제거를 보장하려면 AdSense 대시보드의 **Auto ads/앵커/전면 광고를 끈다**.
서버가 승인한 계정 상태를 확인하기 전에 HTML에 Google 광고 스크립트를 전역 삽입하지 않는다.
이미 무료 세션에서 로드한 제3자 스크립트의 내부 동작까지 언로드로 회수할 수 없으므로
실제 결제 후에는 새로고침한 광고 없는 세션에서 재확인해야 한다.

## AdSense 승인 준비 순서

1. 게시자 ID를 확인한다. AdSense 사이트에 alfinder.kr을 추가한다.
2. 소유 확인용 `<meta name="google-adsense-account" content="ca-pub-실제ID">`를
   head에 넣는 방식을 우선한다. 승인 확인용으로 전역 광고 스크립트를 넣지 않는다.
3. ads.txt가 요구되면 계정에서 제공한 실제 게시자 값을 사용한다. 자리표시자 ID는 배포하지 않는다.
4. 서비스 소개·공개 콘텐츠·연락/개인정보 고지와 크롤러 접근을 확인한다.
   Flutter 페이지 평가 가능성을 실제 심사에서 확인한다. 승인 보장은 없다.
5. 승인 후 반응형 디스플레이 광고단위를 발급해 ID를 연결한다.
6. 적용 지역 동의 설정, 광고 차단 카테고리, Auto ads 꺼짐을 확인한다.
7. 광고 미충전/차단, 무료→광고제거/로그아웃, 모바일·확대·뒤로가기,
   DOM 광고 크기/가림과 네트워크 요청을 검증한 뒤 송출을 켠다.

공식 근거는 [조사 보고서](ad-monetization-research-2026-10-01.md)를 참조한다.
이 체크는 승인·계정 설정·실송출을 이미 수행했다는 의미가 아니다.

## 검증

- 전체 `dart analyze`: clean.
- 미리보기 Flutter Web release 빌드 성공(Wasm dry run 포함), `output/ad-preview/`. 실제 광고 ID 없이 빌드했다.
- Flutter 광고/인증/디자인 경계 테스트 17개 통과.
- Serverpod 광고 제거 권한/생성 등록 테스트 6개 통과(격리 DB).
- 광고 JS 로더 테스트 5개 통과: 초기 무요청, 중복 로드/자동 갱신 방지,
  미충전/스크립트 실패, 계정 전환 후 늦은 광고 요청 차단.
- Flutter 320/390/768/1440px 및 글꼴 2배에서 overflow 없이 본문 스크롤 검증.
- MCP는 기존 공유 개발 폴더를 가리킨다. 이 브랜치를 테스트한 것으로 간주하지 않았고,
  공유 앱을 재시작하거나 사용자 실행 서버를 교체하지 않았다.
- 기존 서버 로그의 read-only DB 헬스체크 정리 오류는 이 작업과 별개다.

## 검토할 파일

Flutter `lib/features/monetization/`, 공통 `PageFrameLeadScope`, `AppViewer`,
`web/ad_loader.js`; 서버 `lib/src/ontology/auth/ad_free_access.dart`.
광고 코드는 생성 파일을 변경하지 않고 기존 Serverpod AuthUser 스코프 저장을 사용한다.

## 계정 연결 진행 (2026-10-01)

Chrome AdSense에서 실제 게시자 `pub-4209548390738211` 확인. 장기 미사용 계정을 재활성화하고 `alfinder.kr`을 사이트 목록에 추가했다. 제공된 ads.txt와 소유 확인 메타태그를 추가했다. 소유 확인과 심사 제출은 운영 배포 후 진행한다. 승인 전 광고 요청은 계속 비활성화한다.

사용자 확정: 광고 제거 월 2,900원, 기존 PG 계약 없음. 자동결제는 토스페이먼츠 공식 v2 빌링 문서 기준 별도 리스크 검토와 계약이 필요하다. 실제 결제·정기 갱신·환불 구현 및 가맹점 개통은 아직 미완료다. https://docs.tosspayments.com/guides/v2/billing

AdSense 광고 단위 `alfinder-content-top` 생성 완료: `3239020318`. alfinder.kr 자동 광고는 사용 안 함으로 확인. 실제 ID를 기본 설정에 연결했지만 ADSENSE_ENABLED 기본값은 false이며 심사 승인과 개인정보 안내 준비 전에는 활성화하지 않는다.
