# 알파인더 인증 메일

가입 및 비밀번호 재설정 메일은 서버에서 Resend API로 발송한다. 맥북 호스팅도 외부 HTTPS 연결과 발신 도메인 설정이 있으면 사용할 수 있다.

## 운영 설정

1. Resend 계정에서 소유한 발신 도메인을 등록하고 제공되는 DNS 레코드로 인증한다.
2. 해당 도메인 발송 권한의 API 키를 만든다.
3. 서버 환경에 `ALFINDER_MAIL_API_KEY`, `ALFINDER_MAIL_FROM`을 설정한다. 발신 주소 예: `알파인더 <noreply@alfinder.kr>`. 실제 검증된 도메인의 주소를 사용한다.
4. 또는 gitignore된 서버 `config/passwords.yaml`의 `shared`에 `authMailApiKey`, `authMailFrom`을 설정한다. 키를 채팅·커밋·스크린샷에 포함하지 않는다.
5. 실행 중인 Serverpod를 재시작한다. 회원 관리에서 발송 설정 상태를 확인한다.
6. 실제 수신 가능한 별도 일반 계정으로 가입 → 인증번호 수신 → 로그인 → 비밀번호 재설정 수신을 확인한다. 스팸함도 확인한다.

설정 존재 표시는 실제 배달 성공을 의미하지 않는다. DNS 인증, 공급자 제한 및 실제 수신을 별도로 확인해야 한다. 현재 구현 테스트는 모의 HTTP 전송과 권한 검증이며 실제 수신 테스트를 대신하지 않는다.

## 동작

- 인증번호는 15분 유효하며 가입/비밀번호 재설정 메일 제목을 구분한다.
- 발송 설정이 없거나 공급자 요청이 실패하면 요청을 실패 처리한다. 콘솔에 인증번호를 출력하지 않는다.
- 요청 제한·인증 실패 제한은 Serverpod 이메일 인증 라이브러리를 사용한다.
- 발송 실패 로그에는 HTTP 상태 코드만 기록하며 인증번호, 메일 본문, API 키, 공급자 응답 본문은 기록하지 않는다.
- API 문서: https://resend.com/docs/api-reference/emails/send-email

## 2026-09-23 실제 연결 및 검증

- `alfinder.kr`: Resend Tokyo 도메인 인증 완료. 가비아에 DKIM TXT, 발송용 CNAME 2개, 초기 DMARC `v=DMARC1; p=none;` 저장. 기존 A/Google 인증 TXT 유지.
- TLS Enforced, 열람/클릭 추적 비활성. `alfinder-auth-server` 키는 Sending access 및 `alfinder.kr` 도메인으로 제한. 서버 비공개 설정 파일은 Git 제외, 권한 0600. 키 값은 문서에 기록하지 않는다.
- 실제 서버 API와 테스트 전용 일반 계정으로 가입 시작 → Gmail 받은편지함 인증번호 수신 → 인증 → 계정 생성 → 로그인 → 비밀번호 재설정 수신/완료 → 새 비밀번호 로그인 검증. 기존 비밀번호와 사용한 가입/재설정 토큰의 재사용 거부 확인.
- 일반 회원의 기업 조회/내 계정 허용, 회원 목록 조회/자가 관리자 승격/비인증 접근 거부 확인. 실브라우저에서 일반 회원 로그인, 관리자 메뉴 비노출, `/admin/accounts` 직접 접근 차단, 모든 기기 로그아웃 후 로그인 화면 복귀 확인.
- 모든 기기 로그아웃 후 기존 refresh token 거부 확인. 테스트 계정의 탈퇴는 잘못된 비밀번호 거부 → 올바른 비밀번호로 성공 → 기존 access token 및 재로그인 즉시 거부까지 확인하고 테스트 계정/임시 자격증명 삭제.
- 서버 관련 테스트 39개, Flutter 관련 테스트 16개 통과. 가입/재설정의 비밀번호 생성 단계는 브라우저 자동 입력이 아닌 API로 검증했으며, 화면은 기존 위젯 테스트와 실제 로그인/접근 차단/로그아웃 검증을 함께 사용했다.
- DMARC `p=none`은 차단 정책이 아니며, `rua` 수신처는 아직 구성하지 않았다. 모든 정상 발신 경로의 인증 확인 후 quarantine/reject로 강화한다. 뉴스레터 도입 시 별도 발신 하위 도메인으로 분리한다.
- 이 검증은 계정/인증 메일 범위이며 공개 서비스의 약관·개인정보 처리 고지 등 출시 준비 전체 완료를 의미하지 않는다.
