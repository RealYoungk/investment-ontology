# 수집 장애 복구 — 2026-09-29

사용자 요청: 상태 설명에 그치지 않고 수집 장애와 잘못된 성공 판정을 수정하고 실제 복구를 확인한다.

## 원인과 변경
- DART/DataGoKr DNS·timeout은 항목 데이터 오류가 아닌 통신 장애다. 즉시 현재 작업을 실패로 종료하고 전체 수집은 15분 뒤 재개한다. DART 점검(800)도 지연 재개한다.
- 통신 장애 때문에 개별 공시의 3회 재시도 제한을 소진하지 않는다. 기존 저장 자료는 유지하며 다음 실행에서 장부를 기준으로 이어받는다.
- 항목 실패가 있는 작업을 성공으로 마감하지 않는다. 시세 실패 기준일도 남은 수량에 포함한다. 중단 시 처리/저장/호출 수를 보존한다.
- 서버 시작 시 최근 작업이 실패했거나 과거 버전의 부분 실패 성공이면, 기존 이어받기 예약이 없는 경우에만 복구 예약을 만든다. 취소/기존 예산 대기는 보존한다.
- 주요정보 기본 상한 18,000회는 유지하고 재무 기본 상한을 19,000회로 분리했다. 과거 주요정보가 재무와 같은 18,000회 상한을 먼저 소진하여 최신 정기공시 검색까지 밀리던 문제를 해결한다. DART 전체 20,000회 중 1,000회는 다른 요청용으로 남는다. 키의 실제 원천 제한 응답은 기존 경로로 처리한다.
- 공시 검색 단계에서 예산이 소진돼 아직 발견된 대기 공시가 0개라도 다음 날 이어받기를 예약한다.
