# 인수인계 마감 기록

## 기준과 범위

Flutter 3.47.5 / Dart 3.13.4 / Serverpod 4.0.0. 로컬 앱의 인수인계 기준이며 외부 운영 배포와는 구분한다. 의존성은 루트 pubspec.lock을 사용하고 CI SDK도 동일 버전으로 고정한다.

이번 변경은 이메일 인증·관리자 권한, 한글 로그인 우선 UI, HttpOnly refresh 쿠키, 수집 동시성/중단 처리, 정정공시 도착 순서, 자동 규칙 재실행, 데이터 예약 카운트다운을 포함한다. 생성 client 변경은 Serverpod 생성 결과다. 로컬 비밀번호·관리자 이메일·DB 파일은 저장소에 포함하지 않는다.

## 새 체크아웃 검증

운영 비밀번호나 기존 DB를 복사하지 않고 다음 절차를 실행한다. 테스트 DB는 config/test.yaml의 dataPath 아래에 자동 생성되며 실제 수집용 API 키가 필요 없다.

```sh
flutter pub get --enforce-lockfile
dart analyze
# 저장소 루트에서 (격리 테스트 DB용 합성 비밀번호 자동 설정)
bash scripts/test-server.sh
# Flutter 패키지에서
flutter test
```

포맷은 CI format.yml과 같이 생성 server/client/test_tools를 제외한 수기 Dart 전체를 검사한다. 실행 앱이 필요한 후속 작업은 사용자가 서버 패키지에서 `serverpod start`를 실행하고 MCP로 연결한다. 비밀 설정·최초 관리자 절차는 [접근 제어](access-control.md)를 따른다. Docker는 로컬 실행/테스트에 필요 없다.

## 실행 증거

- 앞선 로컬 검증: 서버 273개, Flutter 53개; 이후 카운트다운 2개 및 디자인 경계 검증 통과.
- DB 69개 테이블 전체 dump/별도 복원·행 수·무결성 검사 통과. 실제 데이터 재추출은 실행하지 않았다.
- 새 체크아웃과 원격 CI 결과는 이 변경을 검증한 PR 체크와 최종 작업 보고에서 확인한다. 검증 전 성공으로 기록하지 않는다.

## 운영 인계

- 로그인 사용자들은 공용 데이터를 조회하며 관리자가 변경한다. 테마도 공용이다.
- 로컬 인증 코드는 개발 서버 콘솔에 표시한다. 실제 메일 발송은 별도 외부 배포 작업이다.
- 데이터 예약은 시작까지 남은 시간이다. 전체 수집 완료 시각은 API 예산/추가 공시에 따라 변한다.
- 백업/복원은 검증했으나 정기 외부 백업은 구성하지 않았다. 임시 dump를 장기 백업으로 간주하지 않는다.
- 보안/DB 검토 범위와 제외 사항: [추가 점검 보고서](security-db-audit-2026-09-22.md).
