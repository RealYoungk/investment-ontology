# 기업 검색 입력 보정

## 근거와 적용 전략

기본 웹 검색과 Exa로 공식 문서를 비교했다.
- [Algolia Configure typo tolerance](https://www.algolia.com/doc/guides/managing-results/optimize-search-results/typo-tolerance/in-depth/configuring-typo-tolerance): 짧은 입력의 오타 허용은 오탐을 늘린다. 숫자·식별자·약어는 보정 범위를 제한한다. 오타 수를 관련성 순위에 반영한다.
- [Elasticsearch suggesters](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/search-suggesters): 원래 검색과 제안을 구분하고 실제 문서와 일치하는 후보만 남길 수 있다.

현재 규모의 회사명 검색에는 외부 검색 엔진이나 AI를 도입하지 않고 결정적인 보정 후보를 사용한다. 아래 구체적인 규칙과 임계값은 이 제품에 맞춘 선택이며 문서가 한국어 자판의 구현을 지정하는 것은 아니다.

1. 원래 입력의 기업명·영문명·종목코드·대표자 일치를 먼저 평가한다(순위 0–4).
2. `애스 → 에스`만 제한된 표기 보정으로 적용한다(순위 10–14). 전체 회사명이 아니라 알파벳 표기를 보정하므로 SK 등에도 적용된다. `애 → 에`를 일괄 치환하지 않는다.
3. 4–80개의 영문 키 입력은 등록된 한국어 기업명과 공유 발음 규칙으로 만든 이름을 두벌식 키열로 분해해 비교한다(순위 10/11/13). 모음·받침·겹받침과 Shift를 보존하고 전체 대문자는 Caps Lock으로 처리한다. 공백·하이픈·전각 ASCII를 허용한다.
4. 보정 결과도 현재 시장·업종 필터와 페이지네이션을 따른다. 해당하는 기업이 없으면 새 결과를 만들지 않는다. 종목코드 숫자, 짧은 약어, 임의 편집거리, 혼합된 한영 오입력은 추가 보정하지 않는다.

키열 비교는 `dpt`를 `엣`으로 먼저 조합해 버리는 음절 경계 문제를 피한다. `dptmdhdlf`는 공통 이름 토큰으로 읽은 `에스오일`의 키열과 일치한다. 회사별 수동 별칭을 넣지 않는다. 요청마다 외부 API를 호출하지 않고 원래 입력은 보존한다. 응답 스키마와 DB 변경은 없으며 별도의 보정 안내 문구는 이번 범위에 추가하지 않았다.

## 검증

- `애스`, `애스오일`, `dptmdhdlf`, `dotmdhdlf` → S-Oil
- 삼성전자·LG화학·SK하이닉스·KT&G 및 가상 ABC바이오 이름의 두벌식 키열
- 실제 원문 일치 회사가 같은 입력을 보정해 찾은 회사보다 우선
- 정상 `s`, `sk`, `lg`, 종목코드와 초성 검색 회귀
- 짧은 입력·잘못된 종목코드·무관한 키열은 결과를 확장하지 않음
- 겹받침·복합 모음·Shift·Caps Lock·전각 키열 검증
