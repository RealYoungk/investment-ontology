## 2026-10-01 iwinv 운영 전환

alfinder.kr의 API와 전체 DB는 iwinv로 이전했다. 맥을 꺼도 운영·수집은 계속된다. 맥의 이전 DB는 조회 전용이고 FutureCall은 꺼져 있으므로 최신 운영 DB로 취급하지 않는다. 접속·백업·캐시 준비·복구 근거는 [iwinv 운영 기록](iwinv-migration.md)을 먼저 읽는다. 사용자 확정 정책은 공개 조회 유지, 개인 기능에서 가입 유도, 공유 데이터 변경은 관리자만 허용이다. 아래 과거 로그인 필수 정책보다 이번 결정이 우선한다. 개인 저장 기능과 가입 유도 UI는 이번 이전에서 추가하지 않았다. 기존 Serverpod Cloud 체험은 별도로 남아 있다.

### 2026-10-02 첨부정정 재무 원본문과 부분 핵심계정

API 기간 불일치 후 명시적인 첨부정정의 정확 접수번호에 XBRL이 없는 경우에만 공식 DART viewer의 유일한 사업보고서 원본문 접수번호를 확인한다. 원본문 XBRL의 회사·현재 연간기간·연결/별도를 다시 검증한다. FinancialReport와 숫자 Source에는 실제 원본문 접수번호·URL·SHA256을 보존하고, 첨부정정 접수번호의 정상 처리 근거는 financial-attachment-recovery Source와 장부 marker로 별도 기록한다. 다른 회사/기간이나 모호한 원본문 선택은 저장하지 않는다.

별도 XBRL에서 기업 전체의 당기순손익이 없는 경우 값을 추정하지 않는다. 신뢰된 현재 연간 메타데이터와 기업·기간·통화를 통과한 별도 자료 중 자산=부채+자본이 정확히 일치하고 기업 전체 매출·영업이익·영업현금흐름까지 여섯 계정이 확인된 경우에만 부분 핵심계정으로 저장한다. Source에 당기순손익 미확보를 명시하며 전체 재무제표 확보와 구분한다. XBRL 자체가 없는 보고서나 이 조건을 통과하지 못한 자료는 미확보로 남긴다.

XBRL이 없는 명시 첨부정정은 공식 양쪽 viewer의 기업코드와 원본문 연결을 확인하고, 원본문 표지·보고기간·연결/별도 표제·당기 열·원 단위·자산=부채+자본을 통과한 HTML 핵심계정으로 보완한다. 원문 인쇄 계정명을 보존하고 XBRL ID를 만들어 넣지 않는다(accountId=null). 따라서 원문 재무표로 조회할 수 있지만 XBRL ID에 의존하는 투자 지표에 임의 연결하지 않는다. 원본문과 정정 접수번호 및 합성 원문 SHA를 별도로 보존한다. 일반 API noData 전체에 이 경로를 확장하지 않는다.

## 2026-10-02 서비스 소개 영상 준비 상태

`/about`의 2.4MB MP4는 전체 blob 다운로드 후 video.src를 연결한다. 저속 운영 브라우저에서 readyState=0/src 없음과 영상 영역의 초기 흰 배경을 확인했다. 포스터가 도착하면 다운로드 중에도 이미지가 표시되므로 페이지 전체의 흰 화면이나 영상 크기만을 유일한 원인으로 단정하지 않는다.

영상 영역에 Flutter 포스터와 로딩 안내를 덮고, metadata만이 아니라 loadeddata/seeked/canplay에서 readyState >= HAVE_CURRENT_DATA 및 seeking 해제 후 공개한다. 30초 대기 또는 HTTP/미디어 오류에는 spinner를 멈추고 미리보기 안내를 유지한다. 늦게 준비되면 정상 영상으로 회복하며 화면 해제 시 fetch·타이머·리스너·blob URL을 정리한다. 소개 문구·탐색 버튼은 영상과 독립적으로 계속 사용할 수 있다. 전체 blob 방식은 스크롤로 임의 프레임을 탐색하는 기존 동작을 보존하기 위해 유지했다.

격리 정적 빌드에서 영상 12초 지연→준비 완료, HTTP 503 미리보기 유지 및 관련 Flutter 20개 테스트 확인. 최종 검증/운영 증거는 기본 저장소 `outputs/about-video-readiness/`에 보존한다. 실제 광고/결제 설정, 서버·DB는 이 변경 범위에 포함하지 않는다.
