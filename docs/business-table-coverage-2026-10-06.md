# 사업 본문 표 추출·표시 점검 (2026-10-06)

사용자 요청: 원문을 그대로 읽는 화면보다 규칙 기반 구조화와 시각화를 우선한다. 가능한 표부터 구현하고 남은 내용을 함께 검토한다. AI 실행은 이번 작업에 포함하지 않았다.

## 현재 코드에서 확인한 범위

| 표/지표 | 규칙 추출 | 기업 개요 표시 |
| --- | --- | --- |
| 제품·용도 | CurrentProductRows | 제품 카드; 삼성·미코 실제 표 회귀 사례 |
| 제품/사업별 매출 | SegmentRevenue | RevenueComposition |
| 부문 매출·영업이익 | BusinessBreakdownFacts | BusinessBreakdownPanel, 같은 표의 분모로만 이익률 |
| 지역별 매출·내수/수출 | BusinessBreakdownFacts | BusinessBreakdownPanel, 단일 검증된 분할 표만 수출 비중 |
| 수주총액·기납품액·잔고 | OrderFacts, 수식 검산 | 잔고는 기존 표시; 총액·기납품액 이번 연결 |
| 생산능력·생산실적·가동률 | ProductionFacts, 비율 검산 | 사업 지표 추이 |
| 시장점유율 | MarketShareFacts, 회사·기간·열 식별 | 사업 지표 추이 |
| 시설투자 집행 | InvestmentFacts, 기간·단위·합계 점검 | 사업 지표 추이 |
| 연구개발비·매출 대비 비율 | RndFacts, 비율 검산 | 이번 사업 지표 연결 |
| 투자계획 | DocumentFactKind 및 기존 저장 결과 | 사업 지표 표시 지원, InvestmentFacts는 계획을 추출하지 않음 |

15개 DocumentFactKind의 표시 경로를 확인했다. 이는 모든 기업의 모든 원문 표를 지원한다는 뜻이 아니다. 규칙이 맞지 않는 표는 저장되지 않으며 코드가 있다는 사실과 운영 DB에 재추출됐다는 사실도 다르다.

## 이번 변경

- 저장되어도 개요에서 빠졌던 수주총액·기납품액·연구개발비·연구개발비율을 기존 사업 지표 차트로 연결.
- 미검증 draft는 표시하지 않고, 단위별 시계열을 유지하며 연간/반기 기간을 구분.
- 원문 전체를 `원문 펼치기` 뒤로 접고, 그 안에서도 절별로 열도록 변경.
- 운영 데이터 재처리와 클라우드 배포는 수행하지 않음.

## 아직 해결되지 않은 범위

다음은 불가능 판정이 아니라 추가 원문 표 사례와 저장 계약이 필요한 영역이다. 아래 목록을 전 종목의 모든 원문을 조사한 완전한 누락 목록으로 해석하면 안 된다.

1. 투자계획 표: 집행액과 예정액을 섞지 않고 계획 기간·총액·연차별 금액을 별도 보존해야 한다.
2. 원재료별 매입액·매입 비중·가격 변동: 통화/수량 단위와 내수·수입, 품목 변경을 분리해야 한다. 기존 공급 관계 추출만으로 금액 추이가 생기지 않는다.
3. 판매 경로별 금액·비중: 고객명과 판매 경로를 구분해야 하며, 기존 고객 추출의 엄격한 헤더 조건을 넓히면 안 된다.
4. 연구개발 과제·진행 상태·주요 계약: 표로 제시된 상태와 날짜는 구조화 후보지만, 기술 중요도나 사업 영향은 숫자 규칙으로 확정할 수 없다.
5. 위험관리·파생상품 표: 계약 종류·명목액·공정가치·만기·통화를 별도 모델로 유지해야 하며 서로 다른 금액을 한 그래프로 합치면 안 된다.

## 검증

서버 표 추출 회귀 66개 통과, 외부 아크릴 원문 스냅샷을 요구하는 1개는 명시적으로 건너뜀. 실제 표 사례와 단위/기간/경계/검산 실패 거절을 포함한다. Flutter 개요 관련 테스트와 분석 결과는 작업 완료 보고에 기재한다. 운영 전 종목 추출률은 이번에 측정하지 않았다.


## 후속 구현: 추가 표 8종

사용자의 `할수있는것들은 다해줄래?` 요청에 따라 다음 추가 표 규칙을 서버의 `BusinessTableInsights`에 구현하고 기업 개요의 `BusinessTableInsightsPanel`에 연결했다.

| 추가 유형 | 표시 | 현재 근거 |
| --- | --- | --- |
| 원재료 매입액·비중 | 품목별 차트·매입처 필드·전체 표 | 삼성전자/삼성바이오로직스 저장 원문 API와 실제 화면 |
| 원재료 가격 변화 | 명시된 품목·기간·단위별 차트 | 규칙 회귀 사례; 생산 표 오분류 차단 |
| 판매경로별 매출·비중 | 내수/수출 분류를 보존한 차트 | CMTX 실제 저장 원문 발췌 |
| 투자계획 | 계획액 차트, 집행액과 구분 | 계획 연도와 두 줄 헤더 회귀 사례 |
| 연구개발 과제·파이프라인 | 과제·내용·개발시기/단계 필드 | CMTX 실제 연구개발 표 발췌 |
| 주요 계약 | 상대방·계약일·종료일·금액, 차트 페이지, 전체 항목 | 삼성바이오로직스 저장 원문 47개 계약; 세로형 필드/값 회귀 사례 |
| 파생상품 | 명목금액·공정가치·자산/부채, 만기 필드 | 음수·통화·단위 회귀 사례 |
| 금융위험 민감도 | 원문 조건별 손익/자본 차트 | 환율 상승/하락 시나리오와 음수 회귀 사례 |

- 이 결과는 저장된 BusinessDocument에서 공개 읽기 시 결정론적으로 구조화한다. 외부 API·AI 호출·공용 DB 변경은 없다. 원문 DB와 접수번호/출처를 유지한다. 새 DTO는 데이터베이스 테이블이 아니므로 마이그레이션이 필요하지 않다.
- BusinessContent에 nullable tableInsights를 추가했고 생성기는 서버/클라이언트 모델을 갱신했다. 이전 서버 응답에는 새 카드가 나타나지 않으며 기존 응답은 계속 읽힌다.
- 병합된 선행 분류만 이어받는다. 숫자 열로 문자열이 밀리는 불완전 행은 차트로 만들지 않는다. 금액과 비중, 통화와 기간은 별도 그룹이며 빈 값은 0으로 바꾸지 않는다.
- 가격 설명 뒤 생산능력 표가 나오는 실제 사례를 발견해 제목/행 경계로 차단했다. 동일 표 뒤의 새로운 연도 헤더도 이전 표의 데이터로 읽지 않는다.
- 단위가 없거나 복수 통화이면 숫자 차트를 만들지 않고 구조화 필드를 유지한다. 일반 수량 단위/숫자 내 주석은 임의 환산하지 않는다.
- 16개씩 차트를 넘겨 전체 항목에 접근할 수 있다. 전체 행과 추출 근거는 별도로 열 수 있다. 연구개발/계약은 앞 3개를 미리 보여주고 전체 항목 수를 명시한다.
- 새 표는 원문 열/값을 읽은 결과다. 합계·비율의 경제적 동일성을 일괄 검산했다고 주장하지 않으며 카드에 `합계/비율 검산 미수행`을 표시한다. 기존 DocumentFact의 수식 검산 규칙은 계속 적용된다.
- 기존 매출 구성에 서로 중첩될 수 있는 공시 항목의 비중 합계가 100%를 넘는 경우, 안내를 도움말뿐 아니라 본문에 표시하도록 보완했다. 테이블별 완전한 분모 식별을 끝냈다는 뜻은 아니다.

### 실제 확인과 제한

최신 로컬 공개 읽기에서 삼성전자 원재료 표 20행/29개 수치, 삼성바이오로직스 원재료 표 3행/2개 수치 및 계약 47행/47개 수치를 확인했다. CMTX 로컬 최신 사업 본문 읽기는 null이므로 실제 발췌 fixture로 확인했으며, 해당 회사의 로컬 화면 완료로 주장하지 않는다. 모든 기업/연도의 추출률은 측정하지 않았다. 배포는 수행하지 않았다.

새 서버 규칙 및 생성 등록 테스트 12개, Flutter 관련/디자인 경계 테스트 41개 통과. 변경 파일 정적 분석 및 실제 웹 화면 검증을 수행했다. 최종 Flutter Web release 빌드 성공(68.4초). 실제 브라우저에서 계약 차트 1–16 → 17–32 → 33–47 페이지 전환 확인.

여전히 규칙이 처리하지 않는 비정형 표, 설명문에만 있는 숫자/조건, 단위와 분모를 확정할 수 없는 값, 기술적 의미·사업 영향의 해석은 별도 검토 대상이다. 지원한 8종이라는 숫자는 모든 원문 표 형식 지원이나 전 기업 검증 완료를 뜻하지 않는다.
