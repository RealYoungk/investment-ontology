# 광고와 광고 제거 이용권 준비 상태 — 2026-10-01

확정 결정: 공용 기업 데이터는 무료 공개, 일반 광고 우선, 광고 제거 월 2,900원. 공개 고객문의는 이메일 우선. PG 정기결제 계약과 실키는 확인되지 않았다.

## 운영과 이번 PR의 구분

운영은 PR #83 / main 3e92d3e의 광고 배치 준비 상태다. AdSense 소유 확인·심사 요청은 완료했지만 마지막 확인 상태는 준비 중이었다. 광고 요청과 자동 광고는 꺼져 있다. 시장·기업 목록의 본문 배너만 준비했고 상세 정보 열람을 가리지 않는다.

PR #85는 별도 워크트리의 준비 작업이다. 문의·이용권 소개·현재 개인정보 처리 안내와 아래 결제 구현을 포함한다. PR #85의 병합·운영 배포 완료를 뜻하지 않는다. 개인정보 현황 안내를 최종 법적 고지나 동의 취득으로 취급하지 않는다.

## 구현한 결제 흐름

- Serverpod 개인 인증 RPC: 이용권 상태, 카드 등록 시작·완료·취소, 다음 갱신 해지. 공유 데이터 변경 권한이나 관리자 권한은 주지 않는다.
- 서버 상품 금액 KRW 2900. 클라이언트 금액·계정 식별자를 받지 않는다. 토스 v2 SDK 카드 등록창을 사용하며 카드 원문은 우리 앱·서버에 저장하지 않는다.
- 계정에 묶인 10분 일회 state의 해시, 약관 버전·동의 시각을 저장하고 외부 API 호출 전에 원자적으로 사용 처리한다. 성공 URL 방문만으로 이용권을 주지 않는다.
- 구독·기간별 결제 시도 원장, 기간/주문/멱등 키/결제 키 고유 제약, DB 잠금과 트랜잭션. 공급자의 고객·주문·금액·통화·승인 상태를 검증한다.
- 빌링 참조는 소유 계정에 묶인 AES-GCM으로 암호화한다. 서버 전용 모델이며 RPC로 노출하지 않는다. 암호화 키는 서버 비밀 설정에만 둔다.
- FutureCall 갱신, 월말·윤년의 기간 경계, 해지 후 다음 청구 차단, 이미 결제한 기간의 이용권 유지. 결과 불명은 같은 주문 조회로 대사하며 새 주문으로 반복 청구하지 않는다.
- 전액 환불 확인 시 원장 이용권을 제거한다. 탈퇴 중 늦게 승인된 결제는 환불 대기 기록으로 정리한다. 탈퇴는 청구용 키를 즉시 비활성화하고 암호화된 삭제 대기 키를 유지해 공급자 삭제 성공까지 재시도한다.
- Flutter 계정 상태는 서버 원장을 조회하고 1분마다/앱 복귀 시 갱신한다. 만료 타이머는 네트워크 실패 중에도 유료 권한을 제거하고 계정 전환의 오래된 응답을 무시한다.
- 만료 후 재가입은 새 주기·새 주문으로 시작한다. 이용 중 카드 변경은 추가 청구 없이 기간·해지 상태를 유지하고 이전 키 삭제를 대기열에 넣는다. 아직 유효한 해지 이용권은 자동 갱신을 다시 켤 수 있다.
- 현재 주기의 최신 결제 전액 환불은 다음 갱신도 중단한다. 이전 주기의 환불로 새로 가입한 이용권을 중단하지 않는다.
- 결제 화면: 동의 전 시작 차단, SDK 실패·취소 시 대기 state 해제, 서버 검증 결과로만 이용권 표시, 일회 인증 쿼리 제거, 320px 화면 검증.

## 활성화와 재현

광고는 `ADSENSE_ENABLED`, `ADSENSE_SITE_APPROVED`, `ADSENSE_PRIVACY_READY`가 모두 true이고 ID가 유효해야 요청한다. 운영 기본값은 false다. 플래그 자체가 CMP나 사용자 동의 구현은 아니다.

테스트 결제는 development/test/staging에서 `ALFINDER_BILLING_SANDBOX_ENABLED=true`와 test 키만 허용한다. production은 `ALFINDER_BILLING_LIVE_ENABLED=true`, `ALFINDER_PG_BILLING_APPROVED=true`, `ALFINDER_BILLING_PRIVACY_READY=true`, 비어 있지 않은 `ALFINDER_BILLING_TERMS_VERSION`과 live 키가 모두 있어야 열린다. 현재 모두 꺼져 있다.

서버 비밀 설정: `tossTestSecretKey`/`tossTestClientKey` 또는 `TOSS_TEST_SECRET_KEY`/`TOSS_TEST_CLIENT_KEY`; 운영은 각각 Live/LIVE 이름. `billingEncryptionKey` 또는 `BILLING_ENCRYPTION_KEY`는 base64 32바이트이며 임의 교체하면 기존 키를 복호화할 수 없다. 비밀 키·authKey·빌링 키는 채팅·로그·PR에 넣지 않는다. 실제 테스트의 임시 키 파일은 실행 후 삭제했다.

```sh
# 다른 개발 DB와 분리, 9080/9081/9082/9190. 기본 결제·FutureCall 실행 OFF
bash scripts/start-billing-sandbox.sh
# 격리 테스트 DB는 Docker 없이 시작
bash scripts/test-server.sh
node --test investment_ontology_serverpod_flutter/test/web/*_test.cjs
# 실제 브라우저 + 인증 RPC + 격리 DB (PG 응답 모의, 운영 키 불필요)
bash scripts/test-billing-browser.sh
# 깨끗한 커밋에서 전체 검증과 출시 번들 생성
bash scripts/verify_release.sh
```

Serverpod 모델 마이그레이션과 재시작은 해당 워크트리 MCP에서 수행한다. 생성 파일을 손으로 수정하지 않는다. 개발 전용 `tool/ad-sandbox`, `tool/toss-sandbox`는 출시 web 번들 밖에 있다. 실제 공급자 실행기 `server/tool/test_toss_sandbox.dart`는 test 키만 받고 lookup / approve-and-refund를 지원한다.

## 운영 대사 절차

FutureCall은 5분마다 새 기간 갱신과 결과 불명·환불·키 삭제 대기를 처리한다. 결과 불명에는 동일 주문 GET만 사용하고, 환불에는 `refund-원래멱등키`를 재사용한다. 운영 로그의 `Billing result unknown`, `Billing refund pending`, `Billing key cleanup pending`은 원장 ID만 기록하며 키/인증 값/카드 정보를 기록하지 않는다.

반복되는 경고는 해당 PaymentAttempt 또는 Subscription의 상태와 토스 동일 주문 내역을 대조한다. PG 결과를 확인하지 않고 paid/failed로 바꾸거나 새로운 주문으로 재청구하지 않는다. 공급자 삭제 성공 전까지 암호화된 삭제 대기 참조를 유지한다. 상태가 다르거나 부분 환불이면 전액 환불로 처리하지 않고 고객 문의와 공급자 기록으로 정리한다. 실키·암호화 키는 저장소, 채팅, PR, 공개 웹 파일에 두지 않는다.

브라우저 검증 fixture는 `test/`에만 있으며 production에 포함하지 않는다. test 모드의 독립 DB에만 인증 override를 사용하고 기본 테스트 실행에서는 건너뛴다. `scripts/test-billing-browser.sh`가 임시 인증 값·모의 PG 설정을 생성하고 종료 시 삭제한다. 전체 출시 검증은 이 브라우저 검증을 별도로 필수 실행한다.


## 2026-10-01 고지·동의 화면 적용

PR #85에서 `data-notice.html`을 개인정보처리방침으로, `membership.html`을 이용권 약관으로 확장하고 `cookies.html`을 추가했다. 가입 이메일 입력 단계에 미국 Resend 인증 발송 경로를 고지했다. 이것은 가입 동의 원장을 새로 만드는 변경이 아니며, 기존 회원이 동의했다고 소급 기록하지 않는다. 결제 원장의 약관 버전·동의 시각은 기존 서버 처리를 유지한다.

결제 전 화면에는 총 월 2,900원(부가세 포함), 카드 등록 후 첫 결제, 매월 갱신·월말 경계, 갱신 해지와 환불의 차이를 안내한다. 초기 정책은 현재 회차 기간 중 요청 시 해당 회차 전액 환불·이용권/다음 갱신 종료다. 부분 환불은 약속하지 않는다. 법정 권리를 제한하지 않는다. 문의 환불은 운영자가 원장과 공급자 전액 취소 결과를 확인하는 절차이며 셀프 환불 UI는 없다.

광고의 추가 첫 방문 선택은 기본 미선택(거부)이며 브라우저에 90일·버전과 함께 저장한다. 거부 전/미선택 상태에는 Google 광고 스크립트도 요청하지 않는다. 허용 후 Google 메시지 전용 태그가 계정의 Google 인증 CMP를 연결하고, CMP 승인 뒤에만 AdSense 태그를 로드한다. 앱은 TCF 결과가 확정되어야 광고를 push하며, 지역 판정 불명·CMP 실패·필수 쿠키/Google vendor 동의 거부이면 송출하지 않는다. 초기 광고 요청은 non-personalized로 고정한다. 자체 선택은 인증 CMP를 대체하지 않는다. 철회는 현재 진행 중인 광고를 제거하고 동일 출처의 다른 탭에도 반영한다. Google 상세 철회는 기존 동의 API가 연결된 탭으로 전달하며 그 탭이 없으면 가용하지 않음을 표시한다. 정책 페이지 자체에는 Google 광고 태그를 붙이지 않는다.

실제 AdSense 계정에서 `European regulations message - alfinder.kr`가 게시된 것을 확인했다. 대상 모든 지역에 첫 화면 거부 버튼을 활성화하고 메시지 자동 최적화를 끈 뒤 재게시했다. 타 사이트 메시지는 수정하지 않았다. 공식 메시지 게시가 실제 방문자의 지역별 동작 검증을 대신하지 않는다. 광고 활성화 전에 운영 origin에서 `?fc=alwaysshow&fctype=gdpr`를 포함한 허용·거부·철회와 정상 한국 방문을 확인한다. 판정 불명은 거부되므로 동의 API가 준비되지 않은 지역에서 광고가 안 나오는 경우도 확인해야 한다.

운영 서버의 runtime YAML, Docker 로그 설정, backup.sh를 SSH로 읽어 확인했다. 콘솔 10MB×3 회전, 최근 정상 백업 3개 유지다. Serverpod 4.0.0 원문의 로그 기본값은 90일/100,000건/24시간 정리이며 운영 YAML과 환경변수에 retention/cleanup 재정의가 없다. 인증정보 포함 과거 이전 스냅샷은 일반 정기 백업과 별개이며 운영 배포 시 삭제·보존 정리 대상이다. 공개 문구에는 확인한 구현과 제공자 사실을 구분했다.

실결제/실광고 privacy-ready 플래그는 계속 false다. 판매자 연락처·통신판매 신고 적용 여부, Resend 기업 별도 계약 여부 및 Vercel 계약의 호스팅 보존·국외 이전 정보, 거래 원장 5년 만료 시 파기 운영 절차는 실판매 전 확정해야 한다. 알려지지 않은 계약 조건을 임의 기간으로 쓰거나 국외 이전 적법성을 확인 완료라고 주장하지 않는다. 변경한 고지·선택 화면은 아직 main/운영에 배포하지 않았다.

## 관리자 문의 환불 운영 (2026-10-01)

`내 계정 → 회원 관리 → 결제 내역 · 환불`에서 최근 60회차 주문·금액·이용 기간·상태를 확인한다. 문의 발신 이메일과 회원 및 결제일을 대조하고, 현재 회차의 무조건 전액 환불 또는 지난 회차의 오청구·미제공 등 예외 사유를 확인한 뒤 해당 주문의 전액 환불을 요청한다. 화면 확인 단계 뒤 서버에서도 관리자 스코프와 현재 계정/권한, 주문 ID를 검증한다. 카드·빌링 참조·결제사 비밀값은 화면에 보내지 않는다.

1. 요청은 먼저 `refundRequested`로 DB에 저장한다. 현재 주기의 갱신은 즉시 중단하고, 기존 광고 제거는 PG 전액 취소 확인 전까지 원래 만료 시각 범위에서 유지한다. 상태를 성공으로 수기 변경하지 않는다.
2. 동일 주문 GET으로 기존 취소를 확인한 후 필요한 경우에만 전액 취소한다. 원래 주문의 고정 환불 멱등키를 사용한다. 응답 유실·연결 오류면 대기 상태를 유지하고 5분 FutureCall 또는 화면의 재확인으로 복구한다.
3. PG의 주문·결제 식별자, KRW 2,900원 전액 취소·잔액 0이 모두 확인된 경우에만 `refunded`로 전환한다. 해당 이용권을 종료하고 현재 주기의 청구 참조를 삭제 대기로 옮긴다. 이전 독립 주기의 환불은 새 주기를 해지하지 않는다.
4. 요청 직전 시작된 현재 주기의 새 청구가 뒤늦게 승인되면 `refundRequired`로 돌려 추가 승인도 환불한다. 일반 갱신 해지는 이미 결제한 기간을 유지하는 별도 동작이다.
5. PG에서 직접 전액 취소한 현재 유료 회차는 5분 worker의 동일 주문 GET으로 원장과 권한을 일치시킨다(갱신 해지 상태 포함). 과거 만료 회차는 이 화면에서 해당 주문의 환불 확인을 요청해 대사한다. 부분 취소·식별자 불일치는 전액 환불 완료로 처리하지 않고 공급자 기록을 대조한다. 처리 중에는 재가입·갱신 재개·카드 변경을 막는다.

완료 후 고객에게 주문·회차·환불 금액·취소 확인일과 카드사 반영 지연 가능성을 답변하고, 문의/결과는 접근 제한한 운영 자료에 보존한다. 고객 문의 답변을 자동 발송하는 기능은 없다. 탈퇴 계정/60회차 이전 주문은 공급자 주문 기록과 서버 원장을 운영자가 별도로 대조해야 한다. 관리자 로그는 거래 원장 보관을 대신하지 않는다.

## 보존·계약 확인 절차

실판매 전 운영 체크리스트는 `docs/monetization-operations.md`에서 관리한다. 현재 원장은 기간 만료 자동 파기를 구현한 상태가 아니므로 '자동 5년 삭제'라고 안내하지 않는다. 최초 법정 보관 만료 전에 파기 대상 선정·거래/분쟁 보존 예외·백업 교체를 확인하고 실행 이력을 남긴다. 계약 조건·판매자 연락처 및 신고 여부가 미확정이므로 privacy-ready와 실결제 활성화 플래그를 이번 배포에서 켜지 않는다.

2026-10-01 후속 실제/모의 검증 및 최종 로딩 순서: [monetization-preapproval-verification.md](monetization-preapproval-verification.md). 아래 과거 검증 수치는 당시 기록이며 최신 전체 검증은 PR #87/릴리스 증거를 따른다.

후속 보완: 미국 opt-out/GPC/GPP 차단, 현재 유료기간의 PG 직접 취소 자동 대사, 신규·갱신 청구만 중단하는 `ALFINDER_BILLING_CHARGES_PAUSED`는 승인 전 검증 문서 마지막 절을 따른다. Google 동의창 실제 동작은 아직 미완료이며 사이트 승인 때문이라고 단정하지 않는다.
