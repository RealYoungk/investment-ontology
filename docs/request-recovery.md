# 조회 요청의 실패와 복구

Flutter 공통 `ResilientClient`는 생성 클라이언트를 수정하지 않고 상속한다. 명시된 읽기 메서드만 15초 제한과 최대 2회 추가 재시도를 적용한다. 500ms/1500ms 대기와 최대249ms jitter를 사용한다. 네트워크 예외, 시간 초과, HTTP 502/503/504를 재시도한다. 인증 갱신은 SDK의 기존 절차를 유지한다. 400/401/403/404/500, 업무/파싱 예외는 자동 반복하지 않는다. 저장·삭제·결제·수집 실행·검수 결정 등의 변경 요청은 목록에 없으므로 반복하지 않는다. 새 메서드가 자동으로 읽기로 간주되지는 않는다.

Dart Future timeout은 서버 실행을 취소하지 않는다. 제한 시간을 넘은 조회는 서버에서 계속 처리될 수 있으나 늦은 응답이 재시도 결과를 덮어쓰지는 않는다. 변경 요청은 기존 SDK 설정을 유지한다.

수동 복구는 디자인 공통 `ReadFailureNotice`를 사용한다. 버튼을 누르면 ‘다시 불러오는 중…’으로 바뀌며 같은 버튼은 처리 종료까지 비활성화된다. 화면의 로더가 로딩·결과·오류 상태를 소유하고, 실패와 데이터 없음은 별도로 표시한다. 화면에는 내부 예외 문자열을 표시하지 않는다.

적용: 시장 요약/차트의 기존 `MarketLoadNotice`, 매크로 요약·상세, 기업 목록·상세, 재무 섹션·보고서, 공시 표, 사업 원문, 지배구조·인물, 관계망, 지분 묶음 목록·상세, 테마 목록·상세, 주주환원·주주 추이, 스크리너·비교, 홈 최근 공시, 검수 목록. 검수 원문 맥락은 좁은 가로 공간에 맞춰 재조회 버튼을 쓴다. 기존 뉴스·사업 지표·홈 검색 등 이미 복구 버튼을 가진 부분은 유지한다. 개인 기능과 관리자 기능의 인증/권한 제한은 유지한다. 숨긴 테마·지분 묶음은 URL 진입으로 다시 공개하지 않는다.

검증은 `test/read_retry_test.dart`(회복, 최대 횟수, 변경 제외, 권한/업무 오류 제외, 무응답 제한 및 늦은 응답)와 `test/features/macro_page_test.dart`(수동 재시도 비활성화·실패 후 재활성화, 오류→빈 결과, 모바일)를 포함한다. 운영 배포는 별도다.
