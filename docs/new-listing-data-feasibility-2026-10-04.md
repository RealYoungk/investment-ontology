# 신규상장 표시: 계약과 자체 감지 검토

검토일: 2026-10-04 KST. 계약 신청·문의 전송·결제·기능 구현은 하지 않았다.

## 결론

상장일 기본정보만 공개하는 계약의 가격·처리 기간·자동 갱신 전달 방식은 미확인이다. 계약이 불가능하거나 반드시 고가라고 결론 내릴 근거는 없다. 데이터 구매와 공개 웹사이트에 지속 표시하는 권한은 별도로 확인해야 한다.

일일 수집의 차이로 최초 관측을 감지하는 기능은 기존 Serverpod 수집에 추가할 수 있다. 이는 공식 신규상장일이 아닌 자체 관측이며, 원천의 상업적 이용·가공 결과 공개 조건을 자동으로 해결하지 않는다.

## 공식 근거

- KRX 구매 절차: 회원가입 → 상품의 항목·기간·전달 방식·샘플·가격 확인 → 신청 → 결제 → 이용 목적 심사 → 수령. 법인명 입금에는 별도 신청서 안내. 문의 krxdata@krx.co.kr, 02-3774-8904.
  https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA001.jsp
- KRX 데이터 라이선스: 일반 이용계약은 외부 제공 권한, 최종이용사용은 내부 이용. 상장일 단독 상품의 범위·가격을 이 안내만으로 확정할 수 없다.
  https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA004.jsp
- 실시간/지연 시세의 일반 계약 경로는 코스콤 신청·KRX 승인·계약. 이 절차나 가격을 상장일 기본정보에 그대로 적용하지 않는다.
  https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA003.jsp
- 금융위원회 주식발행정보: 상장일 제공, API 호출 무료, 공공누리 2유형. 상업적 이용은 예탁결제원 정보이용계약 필요. 비용 미확인. 문의 portal@ksd.or.kr.
  https://www.data.go.kr/data/15043423/openapi.do
- 금융위원회 KRX상장종목정보 현재 공식 원문: 상장일 필드는 설명에 없음. 공공누리 4유형, 상업적 이용 시 유료 구매와 무단 제3자 제공·재배포 금지 명시. 검색에서 나온 오래된 ‘제한 없음’ 추출 내용과 충돌하므로 현재 원문을 우선했다.
  https://www.data.go.kr/data/15094775/openapi.do

## 좁은 범위의 계약 문의안 (미전송)

알파인더(alfinder.kr)는 국내 상장기업의 공시·재무자료를 탐색하는 웹서비스입니다. 최근 신규상장 기업의 기업명, 종목코드, 시장, 상장일만 공개 화면에 표시하려 합니다. 실시간 시세의 재분배 및 원천 파일 다운로드 제공은 하지 않는 용도입니다.

1. 이 용도에 해당하는 기본정보 상품/라이선스와 비용(초기·월/연·부가세), 최소 계약 기간이 있습니까?
2. 초기 전체 상장일 자료와 이후 일일 변경분을 받을 수 있습니까? API/파일 전달 방식과 업데이트 시각은 무엇입니까?
3. 공개 웹사이트 표시, DB 보관, 상장일 순 정렬, 기간별 신규상장 목록 생성이 허용됩니까?
4. 광고나 유료 개인 기능이 있는 서비스에서 위 정보 자체는 무료 공개하는 경우의 조건은 무엇입니까?
5. 공공데이터포털에서 적법하게 수집한 일일 종목목록의 차이로 자체 ‘최초 확인’ 이벤트만 공개하는 용도는 별도 계약 대상입니까?
6. 신청 서류, 승인 소요기간, 출처 문구, 종료 시 보관/삭제 조건을 안내 부탁드립니다.

## 기존 구현과 자체 감지 설계

확인한 파일: server/lib/src/ontology/ingest/market_snapshot_sync.dart와 models/security.spy.yaml (server는 investment_ontology_serverpod_server).

- 일일 시세 `_storeDay`와 상장목록 `_refreshListing` 모두 새 ISIN이면 Security를 추가한다. 최신 관측일 lastSeenDate는 있지만 최초 관측 이벤트는 없다.
- MarketSnapshotDay는 시세 수집일·행 수 장부다. 상장목록의 모든 페이지와 품질까지 보증하는 독립 장부는 아니다.
- 초기 정상 수집은 기준선만 생성하고 기존 종목 전체를 신규로 표시하지 않는다.
- ISIN 기준으로 종목 이벤트를 보존하고 companyId로 기업 목록을 묶는다. 새 우선주를 새 기업으로 오인하지 않는다.
- 완전한 정상 수집분만 비교한다. 누락 페이지, 실패, 수집 중단 뒤 복구, 과거일 백필로 신규 이벤트를 만들지 않는다. 공백 뒤 첫 관측은 정확한 날짜 대신 관측 구간으로 기록하거나 후보로 둔다.
- 시장 이동, 이름/코드 변경, 재등장, 종목 신규 발행과 회사 최초 등장은 다른 사건으로 구분한다. 영구 firstSeen을 유지해 재등장 중복을 막는다.
- 화면은 ‘최근 처음 확인한 기업’과 ‘수집 기준일’을 표시한다. 별도 공식 근거 없이 ‘신규상장’ 또는 ‘상장일’로 이름 붙이지 않는다.
- Source, 이전/현재 기준일, 수집 실행, 감지 규칙을 기록한다. 계약 확인 전 공개 원천의 가공 결과가 자유롭게 사용 가능하다고 가정하지 않는다.
- 본 검토는 제안이며 사용자 승인된 구현 결정이나 계약 체결로 취급하지 않는다.

## 후속 구현: 자체 최초 확인 (2026-10-04)

사용자가 유료 계약 대신 기존 수집 기반 자체 기록을 요청했다. 새 API·유료 계약·문의 전송은 추가하지 않았다. 이 결정은 원천 이용 조건이 해결됐다는 의미가 아니다.

- Security에 nullable firstObservedDate/firstObservedSourceId 추가. 기존 자료를 임의로 소급 채우지 않는다. 신규 시세 종목을 저장하는 동일 transaction에서 첫 확인과 당시 Source를 기록한다.
- 원천 totalCount와 전체 페이지의 수신 행 수가 일치해야 한다. 직전 양수 시세 수집일이 있고, 새 기준일이 기존 최신 종목 관측일보다 과거가 아니며, 간격 1~4일·전체 행 수가 직전의 95% 이상일 때만 기록한다. 초기 수집·과거 백필·긴 공백·큰 누락은 제외한다. 긴 연휴도 보수적으로 제외되므로 완전한 신규상장 목록은 아니다. 원천 자체의 개별 누락은 완전히 식별할 수 없다.
- 동일 ISIN 기존 행은 새 이벤트를 만들지 않는다. 조회에서는 기존 관측 종목(날짜 null 포함)을 가진 기업을 제외해 새 우선주를 새 기업으로 표시하지 않는다. 기업 연결 전인 종목은 연결 후 조회에 포함될 수 있다. 상장목록 경로만으로 생성되어 시세 최초 관측을 놓친 종목은 표시하지 않는 보수적인 구현이다.
- 공개 읽기 endpoint market.newCompanies, 최근 종목 후보 200건 내 기업 8개. 쓰기는 기존 관리자 수집 경로만 사용한다. 실제 공식 상장일/IPO 목록을 주장하지 않는다.
- 시장 상단 ‘새로 확인한 기업’, 확인일·시장과 기업 상세 링크. 오류·로딩·빈 상태 구분. 시장 필터는 시가총액 구역 위로 이동했다.
- MCP migration 20261004142059567-first-observed-companies 생성·로컬 적용 완료. 자동 코드 생성과 hot_restart 완료. 운영 서버/DB/웹 배포는 하지 않았다.
- 수정 파일 analyzer 이상 없음. 최초 관측 가드·생성 등록 6개, 디자인 경계 3개, 시장 필터 4개 테스트 통과. 로컬 공개 endpoint [] 응답 및 실제 localhost:8100/market 빈 상태 확인. 스크린샷 outputs/new-companies/market.png.
- 새 기업이 실제 유입된 이후의 운영 수집/표시는 아직 검증하지 않았다. 실제 신규 기업을 만들어 운영/로컬 DB에 삽입하지 않았다.
- Flutter release 웹 빌드 완료(90.6초). 이는 운영 배포 완료를 의미하지 않는다.
