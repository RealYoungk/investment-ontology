# 단일 구독 플랜과 가입 가격 보호 설계

작성일: 2026-10-02. 사용자 승인: 포트원 사용, 단일 플랜, 초기 월 4,900원, 구독 유지 중 가입 가격 보호. 목표 가격은 당초 14,900원에서 사용자 제안에 따라 월 19,900원 검토안으로 수정했다. 최종 판매 가격·인상 일정은 미확정이다. 아래 유예기간·구매 견적 유효기간 등 세부 운영값은 설계 기본안이다. 실제 계약·운영 결제·코드 전환 완료를 뜻하지 않는다.

## 상품과 가격

- 단일 플랜 `research_monthly`, 원화 월 자동결제, 표시 금액은 부가세 포함.
- 출시 가입 가격 4,900원. 다음 가격 후보 9,900원, 목표 19,900원. 목표 가격은 현재 판매 실적이 있는 정상가격이 아니므로 취소선 정상가격·할인율·할인 종료 타이머로 광고하지 않는다.
- UI는 ‘얼리버드 월 4,900원 / 구독 유지 시 가입 가격 유지’로 표시한다. 목표 가격은 필요하면 ‘향후 목표 월 19,900원, 일정 미정’으로 설명한다.
- 동일 플랜의 새 기능은 가격 세대와 무관하게 제공한다. AI·대량 내보내기 등 사용량에 따른 원가가 큰 기능은 출시 전 모든 가격 세대에 적용할 공통 사용량 정책을 별도로 정한다. 아직 없는 기능을 현재 혜택으로 판매하지 않는다.
- 공용 기업 데이터의 무료 공개 유지. 현재 유료 혜택은 실제 구현·검증된 광고 제거와 관심기업 확대만 안내한다. 광고 활성화가 안 된 상태에서 광고 제거만을 판매 가치로 과장하지 않는다.
- 가격 인상은 기능 하나마다 자동 실행하지 않는다. 운영자가 실제 제공·검증된 기능 묶음, 결제 전환, 갱신, 해지 이유를 보고 신규 가격 버전을 게시한다. 9,900원·19,900원의 출시일은 미정이다.

## 가격 보호의 경계

| 사건 | 가격 보호 | 이용권·과금 |
|---|---|---|
| 정상 갱신 | 유지 | 가입 금액으로 월 청구 |
| 신규 가격 게시·새 기능 출시 | 유지 | 기존 회원 청구액 변경 없음 |
| 카드 교체 | 유지 | 청구일·회차 변경 없음 |
| 갱신 해지 예약 | 현재 회차까지 유지 | 만료일까지 이용, 다음 청구 중단 |
| 해지 예약 철회 | 만료 전이면 유지 | 명시적 갱신 재개 동의, 자동 재개 금지 |
| 실제 만료 후 재가입 | 종료 | 당시 신규 가격으로 새 구독 기간 시작 |
| 갱신 실패 | 7일 유예 동안 유지 | 아래 실패 정책 적용 |
| 유예 종료까지 결제 안 됨 | 종료 | 이용권 종료, 이후 재가입은 신규 가격 |
| 현 회차 전액 환불 확인 | 종료 | 현 이용권·다음 갱신 종료 |
| 과거 독립 회차 환불 | 현재 보호 유지 | 현재 구독을 소급 종료하지 않음 |
| 계정 삭제 | 종료 | 기존 삭제·빌링키 폐기 절차 적용 |
| 서비스/결제사 장애·운영 청구 중지 | 유지 | 시스템 때문에 가격 보호를 박탈하지 않음 |

초기 첫 결제는 승인 성공 전까지 가격 보호·유료 이용권이 없다. 첫 결제 실패에 무료 유예 이용권을 부여하지 않는다. 카드 등록만으로 영구 가격 선점이 되지 않는다.

## 결제 실패 유예 기본안

- 최초 갱신 예정 시각부터 7일. 상태가 확인된 카드 거절에 한해 +1일·+3일·+6일 재시도, 카드 교체 후 재시도도 동일 회차에서 처리한다. 중복 작업은 DB 잠금·고유 제약으로 차단한다.
- 전송 시간 초과나 응답 유실은 거절이 아니다. 기존 주문을 조회해 승인 여부를 확인하고 새 주문으로 재청구하지 않는다. 실제 결제사 멱등성·거절 재시도 규칙을 검증해 재시도 식별자를 설계한다.
- 유예 중 유료 권한은 임시 유지하지만 ‘결제 완료’로 기록하지 않는다. 결제 실패·유예 만료일·카드 변경 방법을 구독 관리 화면과 알림으로 안내한다.
- 유예 내 승인 성공 시 기존 월 경계를 유지한다. 승인일로 이용 기간을 추가 연장하지 않는다. 유예 종료 후 미확정 거래는 대사 후 정리하며 뒤늦게 승인된 종료 회차는 자동 이용권 부활 대신 환불 조정 대상으로 기록한다.
- 유예 중 해지하면 재시도를 중단한다. 이미 지급받은 회차까지만 이용하며 미결제 유예 권한을 종료한다. 미청구 금액을 자동 채무로 만들지 않는다.
- 운영 `CHARGES_PAUSED`나 공급사 장애는 개인 카드 거절 유예 시계를 소비하지 않는다. 장애 해소 후 별도 안내·재개 절차를 거치며 일괄 소급 청구 금지.

## 체크아웃과 화면

가격 화면: 현재 신규 월 가격, 부가세 포함, 실제 제공 혜택, 매월 갱신, 구독 유지 중 가격 보호, 해지 후 재가입 시 당시 가격 적용을 표시한다.

서버가 생성한 구매 견적은 30분 유효다. 신규 가격이 게시되어도 아직 유효한 견적은 기존 가격을 인정하며 만료된 견적은 새 가격 확인·동의를 요구한다. 첫 결제 전에 최종 금액을 표시한다. 프론트의 금액이나 가격 버전만 믿지 않는다.

구독 관리 화면은 다음을 별도로 표시한다:
- 내 적용 가격과 현재 신규 가입 가격.
- 다음 청구 금액·예정일, 갱신 해지 상태.
- 결제 실패 유예와 종료일, 환불 요청 상태.
- 결제 영수증에는 회차별 실제 청구액을 표시.

‘가입 가격 유지’는 플랜이 존속하고 연속 구독을 유지하는 동안의 약속이다. 임의로 기존 가격을 인상하지 않는다. 서비스 종료 등 상품 존속 불가능 상황은 신규 기능 출시와 구분하고 별도 공지·미사용 기간 처리 절차를 마련한다. ‘평생 무료 업그레이드’ 표현은 사용하지 않는다.

## Serverpod 데이터 설계

현재 상태: `SubscriptionRules.amountKrw=2900`; BillingSubscription에 가입 가격 없음; BillingCheckout에 동의 기록은 있지만 금액 견적 없음; BillingPaymentAttempt에 실제 기대 금액 없음. 따라서 상수만 4900으로 바꾸면 기존 갱신·취소 검증까지 영향을 받는다.

제안 모델:
- `SubscriptionPriceVersion`: 불변 가격 ID, planId, KRW 금액, VAT 포함, 게시 시작 UTC, 정책 버전. 4900·9900·19900은 같은 플랜의 별도 가격 버전이다. 게시 가격 수정은 새 버전 생성으로 처리한다.
- `BillingSubscription`: 현재 연속 구독 세대 ID, 가입 가격 버전·잠긴 금액, 가격 보호 시작/종료 근거, 갱신 실패 유예 시작/종료, 실패 유형. 기존 owner 고유 제약은 유지하고 재가입 세대마다 가격 계약 이력을 따로 보존한다.
- `SubscriptionPriceAgreement`: 구독 ID와 세대, 견적/가격 버전, 잠긴 금액, 실제 동의 시각·정책 버전, 시작/종료 사유. 이전 세대를 덮어쓰지 않는다.
- `BillingCheckout`: 서버 견적 ID, 선택 가격 버전·금액, 만료 시각, 동의 정책 버전. 카드 교체는 새 가격 동의/변경이 아니다.
- `BillingPaymentAttempt`: 세대·회차·기대 금액·통화·가격 계약 ID를 불변 스냅샷으로 저장. 회차 결제 성공/실패/유실·환불을 해당 값으로 검증한다.
- `MembershipView`: 내 적용 금액, 현재 신규 금액, 다음 청구일, 보호 상태, 유예 상태·만료일. 클라이언트 가격 입력은 받지 않는다.

불변 조건: 기존 회차의 기대 금액은 신규 가격 게시나 재가입으로 바뀌지 않는다. 환불도 해당 회차의 실제 승인액·잔액으로 검증한다. 이전 2,900원 거래 취소를 4,900원 기준으로 검증하면 안 된다.

## 포트원 연동

- Flutter Web은 포트원 V2 SDK로 PG의 카드 등록창을 호출한다. Serverpod만 결제 API와 비밀키에 접근한다.
- 기본 PG 검토안 KCP. 업체 계약과 보험·고정비·서비스 업종 승인·카드 등록 경로를 확정해야 운영 활성화 가능하다. 포트원 선택과 하위 PG 계약 완료를 구분한다.
- 공급사 연동은 빌링키 등록/확인·청구·조회·폐기·환불 인터페이스로 분리하고 기존 TossPaymentsGateway 하드 타입을 대체한다. 기존 원장과 월 경계·DB 잠금은 재사용한다.
- 웹훅은 서명 검증 후 결제 조회·금액·통화·주문·상점 대사를 거쳐 반영한다. 중복·순서 역전 이벤트가 가격 보호나 이용권을 복구하지 못하게 한다.
- PG 변경은 기존 빌링키가 이식된다고 가정하지 않는다. 기존 결제 경로를 보존하며 카드 재등록 또는 공급사 지원 이동 절차를 별도로 검증한다.

## 기존 데이터 이행

- 기존 2,900원 거래/테스트 원장 보존. 실제 운영 구독의 존재·금액·동의를 확인하기 전 일괄 금액 변환 금지.
- 실제 2,900원 연속 유료 구독이 존재하면 그 가입 가격을 유지한다. 테스트 회원은 운영 가입 가격 보호 근거로 취급하지 않는다.
- 기존 승인·환불 데이터에서 기대 금액을 보완할 수 없는 행은 추정값으로 활성화하지 않고 대사 대상으로 둔다. 이 상태에서 전체 운영 결제 활성화 금지.
- 신규 초기 판매만 4,900원. 가격 19,900원은 미래 계획이고 활성 판매 버전으로 자동 게시하지 않는다.

## 구현 순서와 완료 기준

1. 가격 계약/회차 스냅샷 모델과 단위 규칙 구현; Serverpod MCP 마이그레이션으로 기존 데이터 보존.
2. 원장·체크아웃·갱신·조회·환불의 2900 전역 상수 의존 제거. 서버 견적과 동의 기록 연결.
3. 유예·해지 예약 철회·재가입 가격 보호 규칙 구현, 인증 및 소유권 검사 유지.
4. 포트원 V2 어댑터와 등록 UI·웹훅 연결. 운영 계약 전 샌드박스만 사용.
5. 가격/구독 관리/결제 확인/실패 화면을 실제 RPC와 함께 검증.

필수 회귀 시나리오: 4900 가입→신규9900 게시→4900 갱신·환불; 구독 카드 교체; 만료 전 해지 철회; 만료 후9900 재가입; 재가입 뒤 과거4900 환불; 거절 후7일 내 회복/만료; 응답 유실·중복 웹훅·동시 갱신; 가격 게시 중 체크아웃 견적 만료; 기존2900 거래 취소; 장애 중 보호 유지; 월말/윤년 경계; 다른 계정 조회·변경 차단.

현재 완료 범위는 설계 문서다. 모델 변경·마이그레이션·포트원 실연동·가격 UI·실결제 검증은 다음 구현 단계이며 아직 실행하지 않았다.
