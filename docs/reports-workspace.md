# 리포트 워크스페이스 · 2026-09-23

기준 배포: main 7c8475c, PR #79. 복구 태그 alfinder-pre-reports-20260923.
개발 브랜치 codex/reports-workspace. 최종 기능은 사용자 E2E 리뷰 후 머지한다.

## 독자 경험
- 공개 목록에서 기업·본문 검색, 시장 필터, 기준일 정렬.
- 원문 그림·차트·출처와 자료 기준일을 보존한다. 기존 분석은 최신 사실로 재검증한 것으로 표시하지 않는다.
- 리포트에서 기업 데이터로 이동하고, 회원은 저장하여 다시 읽는다.
- 발행한 본문을 자동으로 최신 숫자로 바꾸지 않는다.

## 운영
- Serverpod가 본문·초안·발행 포인터·불변 버전·개인 저장을 관리한다.
- 관리자만 초안 저장·발행·공개 해제·버전 복원·기존 원문 이관 가능.
- 동시 편집은 예상 버전을 비교하여 덮어쓰기를 거부한다.
- 새 글은 Markdown, 이관 글은 안전하게 정제한 HTML을 사용한다. iframe sandbox로 원문과 앱을 격리한다.
- 공개 조회는 발행 버전만, 관리자 미리보기는 명시적인 초안 모드만 허용한다.
- 리포트 /research, 재무제표 /financial-reports. 기존 /reports/종목코드는 리포트로 연결한다.

## 검증
권한, 초안 비공개, 발행 후 수정 격리, 이전 버전 복원, 충돌 방지, 본문 정제, 개인 저장 격리,
기존 콘텐츠/이미지 누락 검사, 실제 PC·모바일 읽기 및 관리자 발행 흐름을 검증한다.

- 관리자 편집: /admin/research. 비로그인 사용자는 공개 글을 읽을 수 있고, 개인 저장은 로그인 필요.

- 새 글은 Markdown으로 작성한다. 기존 글은 원문의 HTML을 편집한다. 초안 저장은 공개본을 바꾸지 않으며, 발행·공개 해제와 과거 내용을 새 초안으로 복원할 수 있다.

- dart analyze 문제 없음, Flutter 테스트 92개, 서버 전체 테스트 307개 통과. release web 빌드 성공.
- 비로그인 API로 96/96편의 제목·본문 응답 확인. 번들 본문 내 로컬 이미지 참조 98건 모두 파일 존재.
- 실제 UI에서 관리자 작성 → 저장 → 미리보기 → 발행 → 공개 해제를 확인. e2e-report-review는 비공개로 보존했다.
- 공개 Funnel에서 PC 1440px / 모바일 390px 읽기, 목차, 이미지 3장 로딩, 저장·해제 확인. 모바일 본문 scrollWidth=clientWidth=390.
- localhost의 비로그인 읽기 및 저장 클릭 시 로그인 화면 전환 확인. 일반 계정의 초안·원문·관리 기능 차단과 개인 저장 격리는 서버 통합 테스트로 확인했다.
- output/reports-review/에 화면 이미지와 migration-audit.json을 저장했다. 96편 모두를 손으로 정독한 시각 검수와는 구분한다.
- Serverpod 로그의 리포트 요청은 성공. 개발 중 수정 전 컴파일 오류와 다른 열린 클라이언트의 만료 JWT 기록은 로그에 남아 있으며, 최종 analyze/build/test는 통과했다.

### 리뷰 순서

1. 리포트 목록에서 기업 또는 본문 단어를 검색하고 한 편을 읽는다.
2. 용어를 눌러 설명을 열고, 목차로 이동한 뒤 기업 데이터로 연결한다.
3. 로그인 후 저장/저장한 리포트를 확인한다. 관리자는 비공개 테스트 글에서 편집과 미리보기를 확인한다.

### 범위와 남은 제한

- 이번 구현은 웹 읽기/운영이다. 네이티브 앱 본문 뷰어, 개별 리포트 SSR/검색엔진 메타데이터, 이메일 구독은 포함하지 않았다.
- 기존 React 계산기 등 JavaScript 상호작용은 실행하지 않는다. 원문 시각화의 정적 표현과 수치를 보존한다. 모바일 표는 표 내부에서 가로로 스크롤한다.
- 현재 목록 검색은 작은 아카이브를 메모리에 읽어 필터링한다. 콘텐츠 규모가 크게 늘기 전에 DB 검색 인덱스와 페이지 단위 조회로 변경해야 한다.
- 기존 /reports/ 주소 중 이관 목록의 종목코드는 /research/로, 그 외 숫자 주소는 /financial-reports/로 연결한다. 동일한 숫자가 양쪽에 존재하면 기존 공개 리포트 주소가 우선한다.
- 리뷰 프리뷰는 운영과 같은 맥북 API/DB를 사용한다. 프런트엔드 운영 배포는 PR #79 상태로 유지된다.

### 휴대폰 검토 주소 교체 · 2026-09-24

Funnel URL은 맥에서 HTTP200이어도 사용자 휴대폰 접속 실패가 반복됐다. 검토판을 별도 Vercel 배포 dpl_4bdsp3oB7UmtDANJcQjfgAoLdcQk에 올리고 https://alfinder-review.vercel.app 별칭을 부여했다. 브라우저는 이 주소의 /api를 사용하며 프록시의 DoH fallback을 거쳐 맥 API에 연결한다. 정확한 Origin만 허용하고 MCP 재시작. 운영 alfinder.kr은 promote하지 않았다. 로그인 없이 목록 및 모바일 상세 본문을 실제 확인. 사용자 휴대폰 실접속 성공 여부는 아직 확인 전.
