# shad 후속 이관·입력·실제 QA — 2026-10-03

## 이번 변경

Ant를 다시 도입하지 않고 shad 0.99.4 직접 사용 범위를 넓혔다. Drawer/BottomSheet/PopupMenuButton/ExpansionTile/ListTile/Tooltip/SnackBar/ChoiceChip/InputChip/Chip/InkWell의 기본 컨트롤을 ShadSheet/Popover/ContextMenu/Select/Accordion/Button/Tooltip/Toast/Toggle/Badge로 교체했다. 서비스 목록·필터·계산 기준·관심종목 동작과 URL·인증 계약을 유지한다. 모든 upstream 위젯을 앱에서 사용하거나 검증했다는 뜻은 아니다.

- 모바일 메뉴와 알림/검색/종목 추가, 상세: shad 오버레이 사용. showShadSheet 기본값은 nested Navigator를 사용하므로 서비스 모달 시트는 useRootNavigator:true를 명시한다. 배경 헤더까지 barrier와 semantics에서 제외한다.
- 알림 popover와 관심종목 context menu의 controller를 State에서 보유하고 dispose한다. 기본 overlay focus/Escape/동작은 패키지가 담당한다.
- 기본 ShadIconButton semanticLabel은 내부 tap semantics를 제외한다. 앱 call-site의 이름·활성 상태·onTap을 명시하고 독립 노드로 격리했다. compound badge의 기업 열기와 삭제를 분리했다. Dialog/Sheet closeIcon에도 이름·동작을 제공했다. 이미 닫기 동작을 가진 서비스 상세 헤더는 기본 closeIcon을 숨겨 X가 두 개 나오지 않게 했다.
- AppShell의 nested Navigator BlockSemantics가 앞서 페인트한 헤더/사이드 메뉴를 숨겼다. route 다음에 persistent navigation을 페인트하고 OrderedTraversalPolicy로 탐색 순서를 유지한다. 메뉴는 여전히 접근 가능하며 root modal에서는 배경이 제외된다.
- ShadToggle은 Wrap에서 최대 폭으로 늘어나는 동작이 있다. 서비스 선택 조합과 기존 ChoiceChip 사용처를 IntrinsicWidth로 감싸 compact 배치를 유지했다.
- ShadButton 내 Row는 버튼 내부 Row의 무한 폭을 받으므로 필요한 child를 Flexible로 제한했다. height:0은 upstream 자동 높이이며 긴 서비스 행을 기본 버튼 높이로 자르지 않는다.
- ShadInput은 유일한 패키지 수정 파일이다. enabled/onTap/onFocus, disabled focus 제외, invalid selection 초기화, top Text 라벨 우선/placeholder fallback을 보완했다. 공개 API·외형·onChanged·EditableText 입력 체계는 유지한다.
- [재무표 계약](financial-table-contract.md): 가변 높이 원문·숫자·결측·단일 수평 스크롤 때문에 서비스 표를 유지한다. 고정 48px 행으로 바꾸지 않는다.
- third_party/shad/fonts/PROVENANCE.json: 3개 폰트는 published binary와 동일. 내장 copyright·version·OFL1.1과 SHA를 확인했다. upstream 원본과 고지 보존.

## 입력 분리 실험과 한계

examples/shad_review/lib/input_probe.dart는 같은 Flutter 엔진의 ShadInput과 framework TextField를 비교하는 진단용 별도 entrypoint이며 서비스 화면에 Material 입력을 섞지 않는다. Chrome 자동화 Meta+A/Control+A가 두 입력 모두에서 선택에 실패하고 fill이 기존 문자열 끝에 추가되는 경우를 재현했다. VM shortcut 검사는 통과했다. 따라서 이 자동화 관측만으로 shad에 자체 select-all 구현을 추가하지 않았다.

입력 패치 후 fresh gallery의 첫 semantic focus+fill에서 ‘한글 입력’이 전체 유지되고 필터가 No results로 바뀌는 것을 확인했다. 이는 OS 한글 IME composition이나 VoiceOver 검증을 대체하지 않는다. 실제 OS IME/VoiceOver, nested scroll input ownership, 대규모 표 성능, 로그인 이후 실계정 QA는 남아 있다. 패키지 기본 접근성을 완벽하다고 주장하지 않는다.
