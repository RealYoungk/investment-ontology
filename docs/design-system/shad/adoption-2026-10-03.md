# shad 도입과 Ant 제거 — 2026-10-03

## 확정 결정

사용자가 Ant 전체 포팅 방향을 철회하고 shad 패키지에 완전히 의존하는 UI 기반을 요청했다. Flutter + Serverpod를 유지한다. upstream 위젯의 외형·포커스·상호작용은 패키지에 맡기고 기본 위젯을 직접 다시 구현하지 않는다. 웹 입력 접근성 문제 때문에 published 0.99.4를 third_party/shad에 고정하고 입력 한 파일만 수정한 로컬 패키지를 사용한다. 이는 수정 없는 pub.dev 의존이 아니라 작은 호환 패치를 유지하는 의존이다. 기본 위젯을 AppButton처럼 1:1 재포장하지 않는다.

기준: `shad 0.99.4` + 입력 호환 패치, root `pubspec.lock`의 path dependency. 원본 300개 Dart 파일 중 변경은 input.dart 한 파일이다. `third_party/shad/SOURCE.json`이 원본 SHA와 변경 파일을 기록한다. 출처·커밋·라이선스와 이전 기술 검토는 [technical-review-2026-10-03.md](technical-review-2026-10-03.md), `outputs/design/shad-review/source-lock.json`에 있다. 이전 검토의 ‘앱 미적용’은 검토 당시 상태이며 이 문서가 후속 작업 기록이다.

## 구현 경계

- `lib/main.dart`: ShadApp.custom → 기존 MaterialApp.router/Serverpod AuthGate. 한국어 localization 추가. 기존 URL·인증·관리자 접근 규칙 유지.
- `lib/design/shad_theme.dart`: 서비스 브랜드의 색/한국어 글꼴을 ShadThemeData에 주입. 기본 컴포넌트 동작은 shad가 담당한다.
- 버튼·아이콘 버튼·입력·배지·안내·체크박스·로딩·대화상자: Shad API 직접 사용. 기존 AppButton/AppIconButton/AppTag/AppNotice 제거.
- AppSelect: nullable URL 필터와 명시적인 ‘전체’ 선택만 담당하는 서비스 어댑터. 실제 선택은 ShadSelect/Option. 전체 선택 시 popover를 닫는다.
- AppToggleGroup: 필수 단일 서비스 값과 반응형 줄바꿈을 담당하며 ShadToggle 사용. AppTabBar: URL 탭과 ShadTabs 연결.
- showAdaptiveDetail: 목록을 유지하며 600px 이상 우측, 그 이하는 하단 ShadSheet. 패키지 focus·Escape·back에 위임. 기존 drag-to-dismiss 동작은 제거됨.
- 패키지 오버레이의 ShadThemeScope가 Material ThemeData를 새로 만들기 때문에 서비스 ThemeExtensions를 InheritedTheme.captureAll로 전달한다. 기존 ThemeExtensions·Scaffold·선택 가능한 원문 표시를 위한 Material interop가 있다. 이를 패키지 포크로 해결하지 않는다.
- 기존 AppDataTable은 재무표의 가변 높이·숫자·너비 계산을 가진 서비스 전용 표로 남아 있다. 차트·관계망·사업 카드와 구조용 Scaffold/Material은 서비스 조합으로 남아 있다. ExpansionTile·ListTile·PopupMenuButton·Tooltip·SnackBar·Chip·ChoiceChip·InputChip·InkWell·Drawer 기본 위젯은 shad로 교체했다. 모든 upstream 컴포넌트와 실제 페이지 상호작용을 검증했다는 뜻은 아니다. 독립 갤러리의 단순 목록은 ShadDataTable이다.

## 제거 범위와 복구

Ant 전용 Flutter 패키지·원본 소스·문서·도구·스킬·비교 갤러리를 프로젝트에서 제거했다. 제거 전 파일은 `/tmp/investment-ant-removed-20261003`에 임시 보존했으며 목록은 `outputs/design/shad-review/ant-removal.json`이다. 이는 git에 영구 보관되는 백업이 아니다. 기존 다른 미커밋 작업은 정리하지 않았다. 나머지 React 비교 자료에서 Ant import와 npm dependency를 제거했다. 초기 CSS 모방 시안은 shad 구현 기준이 아니다.

## 다음 유지보수

새 UI는 Shad 기본 컴포넌트를 직접 사용한다. 재무/근거/필터 조합만 서비스 컴포넌트로 만든다. 기존 AppDataTable은 원문·결측·가변 행·폭 계약을 명세한 뒤 ShadTable로 이전할지 결정하며 단순 고정 높이로 바꾸지 않는다.

업데이트는 정확 버전을 변경하는 별도 작업으로 진행한다: pub.dev 버전과 공식 changelog/tag 확인 → 현재 버전과 API/Theme/Input/Overlay/DataTable diff 검토 → 의존성 lock 갱신 → gallery·인증·결제·검색·320/390/768/1440px 테스트 → 웹 빌드와 실제 브라우저·한글 입력 확인 → 사용자 검토 가능한 변경 기록. 자동 최신 추종은 하지 않는다.

## 입력 접근성 호환

원본 raw EditableText에 enabled/onTap/onFocus semantics가 없어 웹 접근성 textbox가 disabled로 표시됐다. 외부 render-node 보정 어댑터는 제거했다. 최종 패치는 ShadInput의 스크롤 내부 EditableText 바로 위에 Semantics와 disabled ExcludeFocus를 추가하고 비활성 전환 시 unfocus한다. 선택·입력·포매터·IME·onChanged는 원래 EditableText에 맡긴다. 공개 API와 스타일은 변경하지 않는다. 패치는 input-accessibility.patch, 원본/변경 SHA는 third_party/shad/SOURCE.json에 기록한다. upstream 수정 시 제거한다.

초기 VM 3개는 활성 textbox focus/semantic edit/selection/clear, 비활성 입력 및 비밀번호 은닉, trailing 버튼 semantics 보존을 검증한다. 실제 Chrome에서 enabled textbox와 focus 후 한국어 필터링을 확인했다. 후속 패치에서 semantic keyboard 요청 전 invalid selection을 텍스트 끝으로 초기화하여 Chrome 첫 한글 fill 누락을 보완했다. top Text 라벨을 editor 이름으로 사용하고 placeholder를 fallback한다. VM 6개는 macOS/Windows 전체 선택·삭제·composing과 라벨을 추가 검증한다. 자동화 Meta+A/Control+A 선택 실패는 같은 엔진의 Material TextField에서도 재현되어 shad 자체의 추가 단축키 패치는 넣지 않았다. OS IME·VoiceOver는 미검증이다.

업데이트 시 published source와 패치를 별도로 비교한다. 기본 컴포넌트 fork 확장은 하지 않고 호환 패치만 명시적으로 관리한다.

스킬의 추적 가능한 원본은 `agent-skill/SKILL.md`이다. `.agents/skills/shad-adoption`과 `.claude/skills/shad-adoption`은 gitignored 로컬 설치 복사본이며 새 checkout에서는 원본을 복사한다.

## 구성 목록

실제 Shad API 참조와 남은 Material 생성자 위치는 `outputs/design/shad-review/migration-inventory.json`에 있다. 이는 전체 upstream 컴포넌트 검증표가 아니라 현재 앱의 사용 범위다. 새 컴포넌트 구현은 shad 패키지 API를 사용하므로 Ant 컴포넌트별 포팅 진행표를 이어가지 않는다.

실제 서비스 빌드와 테스트가 성공하더라도 신규 디자인의 모든 페이지를 실제 브라우저로 검수했다는 뜻은 아니다. 정확한 재무표/차트 검증과 데이터 원천 검증을 유지하고, 사업 UI 변경은 관련 기존 테스트를 함께 실행한다.
