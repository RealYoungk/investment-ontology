# 인증 화면 Shad 적용 — 2026-10-04

홈과 같은 서비스 Shad 테마를 사용하는 로그인·회원가입·이메일 인증·비밀번호 재설정 화면을 정리했다. 인증 카드에는 직접 ShadCard를 사용하며, 입력의 top 라벨과 Lucide 비밀번호 표시 아이콘을 연결했다. 가입과 비밀번호 재설정 마지막 단계의 PasswordField/ActionButton/HyperlinkTextButton, 인증 단계의 ActionButton, 재설정 시작의 패키지 폼을 직접 ShadInput/ShadButton 조합으로 교체했다. 비밀번호 조건 검사는 기존 Serverpod PasswordRequirements와 EmailAuthController에 맡긴다. 기존 개인정보 고지, 공개 탐색, URL 및 권한 계약은 유지한다.

## 검증

- 변경한 인증 소스와 신규 테스트 dart analyze: 이상 없음.
- dart format 적용, git diff --check 통과.
- auth_forms_test/auth_gate_test/design_boundary_test: 13개 통과. 신규 폼 테스트는 320px 로그인·가입·재설정 입력, 빈 입력 비활성, 이메일 입력 후 버튼 활성 조건, 돌아가기 전환을 확인한다. 이메일 검증 debounce 500ms를 기다린다.
- Serverpod MCP hot_restart 성공. DTD는 앱 실행 전 {} 및 spawn 후 null로 반환되어 연결하지 않았다.
- 실제 앱 spawn 및 전체 web build: 기존 생성 Client에서 financial endpoint getter가 누락되어 실패. 이 파일은 작업 시작 전부터 변경된 상태였으며 손으로 고치지 않았다. company_page/financial_report_page/financial_section의 컴파일 실패로 실제 브라우저는 준비 화면에 머물렀다.

실제 화면의 시각 검수, 이메일 발송·인증·가입 완료·비밀번호 변경은 미검증이다. 생성 클라이언트 복구 후 /login에서 실제 검증을 이어가야 한다. 운영 배포는 수행하지 않았다.

## 전체 실행기 재기동 후 복구

사용자가 serverpod start를 재기동한 뒤 Financial endpoint 생성이 복구됐고 generated_code_test 3개가 통과했다. 앱은 localhost:8100에서 정상 실행됐으며 최신 서버/Flutter 로그에 재기동 전 financial 누락 오류가 재발하지 않았다. DTD 연결 및 driver health, 회원가입→로그인→비밀번호 찾기 전환 성공. 실제 브라우저에서 로그인과 회원가입, 320px 회원가입/비밀번호 찾기를 확인했다. 재설정 시작 화면 입력과 버튼 사이 간격을 보완하고 auth 분석/format 및 폼 테스트 3개를 재확인했다. frame sync는 true로 복원했고 text entry emulation은 켜지 않았다.

앞 절의 생성 누락과 브라우저 준비 화면은 복구 전 기록이다. 실제 이메일 발송·가입 완료·비밀번호 변경은 여전히 미검증이다.
