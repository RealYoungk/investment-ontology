# 기업 비교 사용 흐름 점검 — 2026-10-04

검색창을 감싸던 accordion을 제거했다. 기업을 두 개 담으면 입력 상태가 사라지고 검색이 접히던 동작을 없애고 항상 기업 추가 입력을 제공한다.

- 입력 직후 debounce 대기부터 진행 막대와 `검색 중…`을 입력 아래 표시한다. 실패와 성공 빈 결과를 구분하며 수동 재시도는 실제 요청 완료를 기다린다.
- 선택 기업 수와 4개 제한 안내, 이미 담긴 검색 결과의 `추가됨` 및 비활성, 검색어 삭제를 제공한다. 4개에 도달하면 대기 요청을 무효화하고 삭제 후 입력을 다시 활성화한다.
- 요청 번호로 늦게 도착한 검색 응답을 무효화한다. 키보드 Tab/Enter로 결과를 추가할 수 있다.
- 선택 배지는 재무 조회 결과 대신 URL의 선택 기업을 기준으로 만든다. 미확보 기업도 제거할 수 있다. 추가/삭제 시 industryProduct 탐색 문맥을 보존한다. 삭제 기업의 이전 수치는 새 조회를 기다리지 않고 제거한다.
- 금융 계산, API 수집, 인증, 출처 계약은 기존 경로를 사용한다.

## 후속 요청: 검색 결과 표와 체크박스

사용자 요청에 따라 검색 결과의 개별 버튼을 직접 ShadTable + ShadTableCell + ShadCheckbox로 바꿨다. 체크 즉시 비교 URL에 추가하고 해제 즉시 제거한다. 위의 초기 구현에서 추가 후 검색을 비우거나 4개에 도달하면 입력을 막던 동작은 이 구현으로 대체했다. 검색은 계속 가능하며, 4개에 도달하면 선택되지 않은 체크박스만 비활성화한다. 이미 선택한 항목의 해제는 가능하다. 결과가 6개 이하이고 이름/코드만 있는 짧은 표에 upstream 고정 높이를 사용하며 금융 원문 표의 가변 높이 계약을 변경하지 않는다.

360px 미만에서 종목코드는 기업명 아래 표시한다. 긴 기업명은 tooltip으로 전체 이름을 제공한다. 로딩/실패/재시도/빈 결과와 검색어 삭제는 유지한다. 자료 미확보 안내는 비교 조회 완료 뒤에만 표시한다.

변경 파일 정적 분석 이상 없음. 검색/디자인 경계 테스트 6개 통과(320px에서 체크 상태, 선택 후 결과 유지, 해제, 4개 제한과 재활성화 포함). 실제 브라우저에서 삼성 검색 표의 선택 상태, 체크로 추가, Space 해제, 검색어/결과 유지, 연속 체크로 4/4 도달을 확인했다. MCP hot_reload는 응답 timeout이며 실제 서버 종료로 판정하지 않는다.

후속 표 구현의 웹 빌드 성공: `build/compare-checkbox-review` (`/tmp/compare-checkbox-build.log`). 실제 4/4에서 해제 → 3/4 UI 반영 → 다른 기업 체크 → 4/4 복구 확인, 브라우저 console error 0건. 운영 배포 없음.

## 입력창 높이 유지

사용자가 표시한 요소는 기업비교의 `회사명 · 종목코드` 입력이다. 지우기 버튼이 입력 후 trailing에 삽입되어 입력 높이가 늘어나는 현상을 해결하기 위해 입력은 처음부터 48px 높이로 두고 빈 상태도 28px trailing 공간을 예약한다. 잘못 적용한 상단 통합검색 크기 변경은 되돌렸다. 입력 전/후/삭제 후 동일 rect 검사와 기존 검색/포커스 총6 tests 통과, 변경 파일 analyze 이상 없음. 이번 브라우저 재확인은 localhost:8100 연결 거부로 제한됐다. 서버 시작/재시작은 직접 하지 않았다.

## 2026-10-05 모바일 세부 수치 표
