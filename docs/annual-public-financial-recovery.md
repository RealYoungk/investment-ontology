# 공식 원문 재무 보완 수집

OpenDART 재무 API의 `자료 없음`은 공시 원문에 숫자가 없다는 뜻이 아니다. 최근 5개년·최신 중간보고서 범위의 API 빈 응답은 보존하고, 공식 DART 원문의 접수번호·회사·기간·재무 구분을 검증한 별도 경로로 보완한다.

## 원문 수집

연간 보고서의 연결·별도 API 응답이 모두 비어 있던 대상은 회사별 최신 기간을 우선하여 한 실행에 최대 10기간만 처리한다. 공식 XBRL을 먼저 검증하고, 지원하지 않는 형식이면 동일 접수 원문 HTML을 검증한다. 일반 보고서를 이전 접수로 바꾸지 않는다. 첨부정정은 공식 연결 원접수를 별도 검증한다. 공개 원문 요청은 최소 1초 간격으로 시작하고 API 예산을 소비하지 않는다. 개별 실패와 원문 자료 없음은 구분하며, 실패는 최대 3회·연속 6회 회로 차단과 취소·재개 규칙을 따른다.

저장 자료는 전체 재무제표가 아닌 검증한 핵심계정이다. HTML은 실제 인쇄 계정명·표시 단위·당기 열과 원 단위 환산 근거를 보존하며 XBRL 계정 ID를 만들어 넣지 않는다. 원문 URL과 SHA256, 접수·회사·기간, 기존 API 빈 응답 상태는 출처와 감사 기록에 남긴다. 원문에 연결재무제표 비작성을 명시한 경우만 증거를 가진 별도 비적용 결과로 인정한다. 일반 빈 화면이나 추정은 실패다.

HTML 보완 경로는 현재 검증된 1년 연간 표지와 표 형식을 지원한다. 실제 단기 연간 기간은 XBRL의 공식 보고기간 선언이 있을 때 그대로 검증하며, HTML에서 1년으로 추정해 저장하지 않는다. 현재 API 빈 응답 656건의 보존된 대상 큐에는 리츠 회사가 없다.

## 표시 기준

재무 화면과 스크리너는 보고서 출처의 접수번호와 공시 원장의 회사·연도·보고서 종류·실제 결산월이 일치하는 자료만 사용한다. 계정도 선택한 보고서의 회사·연도·구분·출처가 일치해야 한다. 다른 월을 같은 기간의 정정 이력으로 섞지 않는다.

현 DTO는 회계연도와 보고서 종류별 하나의 기간을 사용하므로, 동일 연도에 여러 연간 기간이 있으면 최신 실제 결산월을 선택한다. REIT의 모든 단기 결산을 별도로 표시하거나 12개월 TTM으로 재구성하는 기능은 이 변경의 검증 범위가 아니다.

## 완료 판정

저장 상태만으로 완료를 주장하지 않는다. 실제 기간·원접수 출처·당기 금액 보유 여부, 원문에 실제 자료가 없는 경우, 수집 실패, 아직 대기 중인 항목을 구분한다. 부분 핵심계정 저장은 전체 계정 복구나 모든 파생지표의 확보를 의미하지 않는다. 공시 주요정보 28종은 이번 우선 마무리 범위에서 제외한다.

## 당기 금액이 전부 빈 기존 보고서

선진의 특정 2024년 접수는 기존 API가 비교기간만 반환했지만 공식 XBRL에 당기 핵심계정이 존재한다. 이 접수의 검증된 7개 당기 행만 별도 원문 출처로 추가한다. 기존 숫자와 비교기간 행·출처 ID는 바꾸지 않고, 기존·새 원천 연결과 SHA를 감사 기록으로 남긴다. 보고서가 선택하는 현재 출처는 새 당기 핵심계정으로 전환하며, 원문 표는 이전 비교기간 행과 당기 복구 행을 구분한다. 7개 이외 계정의 확보나 전체 비교값 재검증을 주장하지 않는다.

원문 당기 열도 실제로 빈 코스나인 접수는 이전 연도의 숫자로 채우거나 0으로 만들지 않는다. 이 경우는 당기 원문 미확보 상태를 유지한다.
