# Fixed official issuer documents

The normal business-document scheduled worker preserves 27 reviewed documents for 12 companies: the existing 15 fund PDFs plus 12 DART financial chapters (nine issuers). The additional DART documents are eight IPO registration financial chapters, Brils' 2023–2025 own audit financial chapters, and Brils' IPO prospectus financial chapter. They are partial report bodies, not a collection of complete original filings. Source shell and chapter SHA256, exact viewer coordinates, issuer and printed period are pinned in source and in the manifest. No discovery URL or wildcard URL is accepted.

Only private immutable HTML/PDF cache and source-backed `issuerDocuments` research metadata are stored. Public rows are link-only and explicitly `numericState: notExtracted`, with no financial values. Nothing creates regular filing, financial report, fact, or business-body ledger rows. The data-page validator accepts the same exact new DART metadata pins. Split-company parent documents are excluded; their child-company coverage remains unresolved. Brils 2021–2022 and KBIF independent own 2021–2023 annual files remain unresolved, not classified absent or not due. IPO chapters contain comparative figures but those do not establish independently collected annual documents.

The persistent worker cache must be configured with `ISSUER_DOCUMENT_CACHE_DIR` and remain private. Previously verified HTML bytes can be prefilled under SHA256 `.html` filenames; the runtime rechecks SHA256 and issuer-shell binding before any metadata store. Otherwise it uses the exact pinned official HTTPS URLs, never redirects. Public content is never mirrored. A changed official response or partial GET cannot create a falsely complete company snapshot. Existing snapshots/history remain intact.

Validation: 37 backend pure tests and 5 UI tests passed, including existing fund contracts, cross-company/node/hash mutations, partial-source protection, private-cache replay, cancellation, numeric/raw-content restrictions, 320px layout, and stale reload. The integration test adds actual Brils own source-to-snapshot replay, failed chapter fetch, pending subset detection, and unchanged financial/body/API ledgers; it must run in the owner's isolated test runner. No production database mutation was performed to prepare this change.

Follow-up: company fetch/storage failures are isolated so other issuers continue. The normal business job message records separate issuer company/document counts, setup failures and causes; raw failure sets failed status while preserving all body period and API counts. Cancellation is retained. Existing daily/startup recovery handles retries; raw collection never replaces a later budget-resume queue or creates a permanent-failure tight loop. Startup verifies actual private cache bytes for eligible issuers as well as exact metadata/Source, so missing or corrupt files remain pending.
