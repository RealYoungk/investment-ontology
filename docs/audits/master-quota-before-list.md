# 기업마스터 목록 요청 전 DART 한도 확인

corpCode.xml도 공유 DART 호출로 계산된다. 기존 코드는 목록을 먼저 받은 후
기업개황 루프에서만 남은 예산을 확인해, 이미 일일 한도를 쓴 날에도 목록
GET을 추가했다. 이제 목록 요청 전 취소와 공유 사용량을 확인한다.

기본19900회 soft limit은 유지하고, 설정이 더 커도20000회 hard limit을
넘어 호출하지 않는다. 개황 요청 전에는 local meter를 반영하고 최신 공유
사용량을 재확인한다. 한도 소진이면 API0으로 대기 상태를 기록하고 다음
KST 자정+10분 변경분 재개를 예약한다. 성공을 기록하지 않으며 기존 기업
변경일·프로필·DartCorpStatus와 이미 저장된 변경 사항은 삭제/초기화하지 않는다.
실행 전 이미 취소된 작업은 목록·개황과 재예약을 수행하지 않는다. 실제 원격020 응답의
기존 제한 안내와 재예약 경로는 그대로 유지한다.

격리 회귀는19900기본/20000공유상한/명시0에서 요청0·정확예약, 취소예약0,
변경일·상태 불변, 날짜가 바뀐 후 변경된1기업만 개황 재개를 확인한다.
시계 주입은 예약/저장 시각 검증용이며 공유 meter의 KST일 집계는 기존
실제 시계 정책을 유지한다. 생산 API나 DB를 직접 변경하지 않는다.
