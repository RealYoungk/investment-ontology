## 선정

## 확인하고 수정한 공통 패턴

1. **합계를 제품으로 오인**: 단순합계, 합계(연결조정 전/후)를 분모로 인식한다. 한화에어로스페이스·현대제철 등에서는 누락이 복원되고 DL이앤씨에서는 잘못 포함하던 단순합계가 제외됐다. 연결조정 전 비중의 합이 100%를 넘을 수 있으므로 임의로 100%에 맞추지 않는다.
2. **2열 하위 머리글**: 오로라 형태뿐 아니라 LG에너지솔루션의 사업부문/주요제품 아래 `매출액 | 비율`을 받는다. 기간별 숫자 칸은 오른쪽 기준으로 다시 찾고 기존 비율 검산을 유지한다.
3. **시간 단위와 생략된 %**: HD현대중공업의 `18,437천M/H`와 농심·LS ELECTRIC의 표 단위 `%`만 적힌 가동률을 받는다. 분자·분모의 인쇄 단위와 배율이 같을 때만 검산한다. 시간을 제품 생산능력·생산량으로 저장하지 않는다. 국내·해외 합계 이름도 구분한다. 원문에 있는 100% 초과 가동률을 잘라내지 않는다.
4. **연구개발비 표 변형**: 한일단조의 당반기/전기, 기가비스의 연구개발비 단일 총액 행, LS ELECTRIC의 병합된 연구개발비용/합계, 삼성SDS의 전년 반기와 연간 중복 기 번호를 인식한다. 비율과 같은 기간 재무 매출 검산이 통과할 때만 API가 확정 값을 제공한다.
5. **영업수익 표**: NAVER의 영업수익 총계와 플랫폼별 비중을 읽는다. 영업수익 총계를 네 번째 제품으로 넣지 않는다. 원문이 같은 표를 두 번 실어도 중복 사실을 만들지 않는다.
6. **표시 누락**: 원문 비중 셀에 `%`가 없으면 화면이 `—`를 출력하던 문제를 수정했다. 숫자만 적힌 비중은 정확히 지정된 서버의 자동 검산 출처를 가진 사실에 한해 표시하고, 다른 검증·초안·같은 금액이 여러 기간에서 겹치는 경우에는 추정하지 않는다.

개선 영향을 확인한 기업: 한화에어로스페이스, HD현대중공업, DL이앤씨, 현대제철, LG에너지솔루션, LG전자, 두산에너빌리티, 한일단조, 기가비스, 농심, NAVER, LS ELECTRIC, 삼성SDS.

## 미공시로 뭉뚱그리면 안 되는 남은 항목

- **원문이 명시한 생략/부재**: 씨에스윈드는 생산법인별 생산능력·실적·가동률을 영업기밀로 생략하며 R&D를 별도 계상하지 않는다고 명시한다. 기가비스는 주문별 사양으로 생산능력 산출이 어렵다고 명시한다. 오로라는 수주 비공개와 수작업 생산 설명이 있다. GS건설의 확인한 자이에스앤디 구역은 생산 개념을 적용하기 어렵다고 설명한다. 이를 0으로 만들지 않는다.
- **정량 공시는 있으나 검산 분모 없음**: S-Oil의 생산실적/가동률 표, 아모레퍼시픽의 사업소별 평균가동률 2열 표는 수치가 존재한다. 현재 규칙으로 검산할 수 없으므로 확정 숫자 사실과 구분한다.
- **서로 다른 표를 결합하면 오류**: 영원무역의 매출 비중과 연결조정 전 금액은 서로 다른 표이므로 바로 합치지 않는다. 이마트의 회사 묶음·매출형태·소계를 한 번 더 합산하지 않는다.
- **업종 전용 구조 필요**: 현대자동차의 제조서비스/금융 및 매출/영업이익/총자산 구분, 삼성생명·삼성화재의 보험/준비금/운용자산, 미래에셋증권의 가로 사업부문별 영업수익/비용 구조는 제품 매출 표와 구분해야 한다.
- **공통 미수집**: 50개 모두 최신 반기 배당·자기주식·주식총수 상태가 `pending`이다. 원문 부재로 판단할 수 없다. 기존 수집기는 해당 최신 중간보고서 항목을 포함하지만 로컬 수집을 실행하려면 관리자 인증이 필요하다. 오로라 한정 수집 시도는 HTTP 401이었으므로 50개 수집으로 확대하지 않았다.
- **기존 DB 값과 신규 규칙의 차이**: 읽기 전용 복원은 활성 문서·접수번호·회사·기간 연결을 확인하며, 같은 이름·단위로 다른 금액이 나오는 여러 표가 있으면 문서 단위 복원을 보류한다. 기존 검증 사실을 임의로 새 값으로 덮어쓰지 않는다. 저장된 값 전체의 재추출에는 관리자 재처리가 필요하다.

수정 전 단어 기반 후보 신호는 매출 20, 가동률 17, R&D 13건이었다. 수정 후 14, 12, 6건이다. R&D의 매출액 대비 비율 때문에 매출 후보가 발생하는 경우처럼 거짓 양성이 있으므로 **후보 수 감소를 정확도 상승률이나 해결률로 해석하지 않는다**.

## 반복 실행

새 회차에는 새 출력 디렉터리를 사용한다. 기존 캡처 폴더를 다시 지정하면 저장된 스냅샷을 재사용한다.

```sh
# 저장 API 캡처: 관리자 수집/외부 AI 호출 없음
python3 scripts/audit/business_50.py \
  docs/audits/business-50-2026-10-12/selection.json \
  tmp/business-50-pass-02/capture

# 실제 DART viewer 본문 재조회. shell만 얻은 것은 성공으로 세지 않음
python3 scripts/audit/business_primary.py \
  tmp/business-50-pass-02/capture/corpus.jsonl \
  tmp/business-50-pass-02/originals

# 서버 패키지에서 실행. DB 변경 없는 파서 재검사
cd investment_ontology_serverpod_server
dart run tool/business_tables/audit_corpus.dart \
  ../tmp/business-50-pass-02/capture/corpus.jsonl \
  ../tmp/business-50-pass-02/parsed.jsonl
dart run tool/business_tables/audit_selected.dart \
  ../tmp/business-50-pass-02/capture/corpus.jsonl \
  ../docs/audits/business-50-2026-10-12/selection.json \
  ../tmp/business-50-pass-02/diagnosis.json
```

다음 개선 순서는 공통 미수집 해소 → 제조서비스·금융 및 다단계 유통 표의 분리 → 검산 불가능한 공시 수치의 원문 표시 방식 개선이다. 이는 이번 진단의 작업 우선순위이며 자동 예약이나 사용자 확정 일정은 아니다. 매 회차 동일 표본의 회귀 확인과 새로운 업종/표본의 확장을 함께 수행한다.

## 파일과 실행 상태

- 실제 회귀 표본과 원문 출처: 서버 `test/fixtures/business_50/sources.json` 및 `.txt` 10건.
- 캡처 450개 API 응답·원문 HTML·수정 전후 파서 결과·50개 화면 트리·테스트 로그: `tmp/business-50-audit/`.
- 코드 변경 및 `dart analyze`/`dart format` 완료. 관리자 권한 우회·DB 수동 수정·AI 서술 숫자 입력·운영 배포 없음.
- 개발 runner의 오래된 분석 상태로 생성 코드가 일시적으로 disclosure endpoint를 제외했지만, 생성 파일을 수동 편집하지 않고 MCP 재시작과 정상 소스 재분석으로 복구했다. 생성 등록 테스트 통과 및 최종 공개 API 200 응답을 확인했다.
- Flutter 개발 컴파일러 캐시 오류가 있어 이번 점검에서 띄운 Flutter 프로세스만 종료하고 Serverpod MCP로 다시 실행했다. 최종 비중 표시의 실제 화면 확인 결과는 아래 실행 기록에 추가한다.
- GBrain은 이전 조회에서 live serve/PGLite 잠금 오류가 있었으며 이 회차 기록의 GBrain 저장을 확인하지 못했다. 이 문서와 명단·판정표를 다음 회차의 기준으로 사용한다.
