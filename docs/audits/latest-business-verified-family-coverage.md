# 최신 보고서 기준 사업본문 확보 지표

기존 정확 최신접수 본문2740/2763과 사업본문 범위15289/15289는 정의가 달랐다. 첨부정정10개는 정상 원접수의 실제 본문과 Source를 보존해 수집했기 때문에 최신접수와 본문의 접수번호를 정확히 비교하는 지표에서 제외됐다. 새 읽기 계산은 정확 접수 본문 또는 공식 가족목록 원문으로 검증한 10개 고정 관계만 포함한다. 나머지13개 기업은 정기보고서 접수 미식별이며 분모에서 제외하거나 영구 자료없음으로 승격하지 않는다.

고정 관계마다 실제 공식 현재 shell의 가족목록에 원접수와 동일 보고서 종류가 있고, 회사 법인코드가 일치함을 공식 fixture로 검증했다. DB Source의 사업본문 기간검증 감사가 있는 것은5개 연간이며, 나머지5개까지 DB 감사가 존재하는 것처럼 표현하지 않는다. 원접수의 company/법인코드/실제보고기간 원장·본문/출처·공식 고정 가족목록 증거를 함께 검증한다. 머니무브 표지회사명 오표기는 이전 정책의 공식 같은법인·가족관계·기간 검증 범위에만 해당하며 현재 회사명과 표지가 정확히 일치한다고 주장하지 않는다.

현재 대상 기업과 본문 소유자, 본문·공시 원장 연도, 보고서 종류·실제 종료년월, 실제 원접수, 원천 Source.kind/ref 및 공식 접수 바인딩 URI, 본문 비어있지 않음, business section stored를 검증한다. 임의의 같은기간 원본문, 다른회사, 다른 접수, 이전기간, 다른 출처, 빈본문은 제외한다. 최신정정 CF나 숫자 전체가 원문과 동일하다는 주장은 본문 확보 지표의 범위 밖이다.

이 변경은 기존 coverage DTO의 숫자 읽기 계산만 바꾼다. API 계약·모델·코드생성·마이그레이션 변경0이며 본문/Source 필드 쓰기0. 최신 기준을 충족하는 원접수 보존10개가 모두 존재하는 현재 스냅샷에서는2750/2763이고, 향후 다른 접수는 이 고정 관계로 자동 인정하지 않는다.

테스트는 실제10개 공식 가족목록 양성, 격리 DB의 owner/year/kind/접수/Source/빈본문/미식별 경계 및 조회 후 원본문/Source 불변을 확인한다. 새 운영 쓰기나 공식 원문 조회는 없다.
