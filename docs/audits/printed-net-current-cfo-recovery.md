# Direct current totals in two exact annual sources

Two original OFS bodies from the failed inventory were read directly and packaged with their same-receipt shell, cover, URLs and SHA-256. No external numeric estimate, opposite-basis amount or prior-year substitution was used.

- Hite Jinro Holdings FY2021, receipt `20220317000713`: gross operating revenue is the directly printed `영업수익:` row (40,214,502,759 won). Its CF table has an entirely blank `I.영업활동현금흐름` section caption followed by the directly printed `영업활동으로 인한 순현금흐름액` total (18,142,951,111 won). The parser skips the caption only when exactly one later net total exists in the same dated primary table, with complete unspanned cells. It preserves the original account labels. Both finite aliases are also supported by FinancialAccounts and its shared SQL mapping.
- WiWorld FY2024, receipt `20250320001147`: the CE table prints three annual profit rows. The independently dated current window is 2024-01-01 through 2024-12-31. Its whole current profit (401,146,048 won) agrees with CIS, and closing whole equity (8,715,189,467 won) agrees with BS. The Roman/current-window proof selects that actual window, rather than rejecting all three printed profit rows as ambiguous. The malformed earlier CF comparison cell `1,9966,088,893` is not read or repaired; this package validates seven current-period core accounts only.

The original current rows were checked against the raw table cells before pinning `expected-rows.json`. Packaged source identity/scope/byte-mutation checks pass (29 tests). Direct total, duplicate, component and malformed-current-amount checks plus existing Novmeta and FinancialAccounts regressions pass (37 tests). The normal admin queue and repeat-run preservation checks pass for both sources (2 isolated DB tests; `/private/tmp/io-direct-total-two-normal-db.log`). No production write has occurred. This is current core-account recovery, not extraction of every statement row or every comparison column.
