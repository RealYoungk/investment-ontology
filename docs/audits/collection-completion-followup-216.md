# 수집 복구 후속 216개 고정 원문 기준

운영 첫 배포(6c445de8896e1b30e5fb2825dcb90f328468109f)의 정상 큐에서 고정 원문 110개 기준을 처리했다. 핵심 계정 재무자료 84벌(43개 기업), 원문이 명시한 기준 비해당 23건, 승인되지 않은 범용 six-core 저장 거부 3건이다. 요청 범위 15,289기간의 실패 장부와 실제 미확보 기간은 같은 조회에서 각각 238→174로 줄었다. 이는 재무제표 전체 행 수집 완료를 의미하지 않는다.

후속 registry는 189에서 216으로 늘었다. 추가 27기준은 각 보고서의 정확한 회사·접수·연도·기간·연결/별도·공식 원문 URI/SHA와 당기 직접 핵심계정 및 독립 BS/CE/CF 검산을 고정한다. 기존 44개 기준 비해당 자료와 승인되지 않은 six-core 3개의 저장 차단은 보존한다. 일반 매출 합산, 임의 0 생성, 과거 수치 보정, 시도 횟수나 API 한도 초기화는 하지 않는다.

추가 자료의 격리 정상 큐 검증은 기존 14기준 관련 16테스트, 보험 10기준 10테스트, NH 1테스트, DB FY2022 CFS 1테스트, 대신 FY2022 OFS 1테스트다. 별도로 원문 불일치 2건 거부, 종목 재연결 식별 충돌 3테스트를 검증했다. Source·반대 기준·원형 계정명·인쇄 단위와 원 환산 근거·카운터·API0·한 번만 저장하는 재실행을 확인했다. DB/NH의 앞선 환경 실패나 테스트 필터 미일치는 각 감사 문서와 로그에 보존하고 최종 PASS와 구분한다.

대신증권의 BS 현금및예치금과 CF 현금 차이는 같은 접수 주석6(1)/36(1)의 직접 정의와 당기·전기 구성표로만 검증한다. 주석6(2)의 전기 제한예치금 1천원 차이는 사용하거나 보정하지 않는다. CAPEX의 인쇄 부호는 Source 증거에 보존한다. 기존 핵심계정의 취득액 정규화와 원형 부호 저장 방식이 함께 존재하며, 화면/FCF는 기존 절댓값 규칙을 사용한다.

수집 범위는 가장 최근 다섯 연간 회계연도와 최신 연간보다 새로운 중간보고서 한 개다. 과거 저장 자료를 삭제하지 않는다. 종목 재연결은 관리자 권한을 검사하는 별도 DB 작업이며 API 키 없이 실행하고, 회사/종목 법인등록번호 충돌을 거부한다. 화면은 최소 하나의 금액이 저장된 기간과 전체 재무제표 행 수집을 구분하고, 원문 부분 핵심계정의 Source 범위를 표시한다.

직전 c6491d31은 clean pre-push에서 서버 346파일/14묶음, Flutter 320테스트(기존 skip2), Python20테스트를 통과했다. 최종 216 통합본은 별도의 전체 pre-push와 배포 검증을 수행해야 한다. 변경에는 .spy.yaml 모델, generated 코드, DB migration이 없다.
