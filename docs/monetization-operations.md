# 수익화 운영 체크리스트

이 문서는 유료 판매·광고 활성화 전에 확인할 구체적인 작업과 확인 결과의 기록 위치를 정의한다. 체크리스트 작성이 승인·계약·법정 요건 충족을 뜻하지 않는다.

## 판매 개시 전

- 공개 상품: 월 2,900원 VAT 포함, 다음 기간 자동결제, 해지 경로, 현재 회차 전액 환불, 문의 이메일, 약관 버전. `membership.html`과 결제 전 화면을 함께 확인한다.
- 판매자: 사업자등록증으로 확인한 영앤리치/김영진/345-51-01199와 공개 문의 이메일을 사용한다. 주소·공개 연락처 및 통신판매 신고 적용 여부는 최종 PG 신청/판매자 표시에 맞춰 확정한다. 비공개 PG 연락처를 임의로 공개 페이지에 옮기지 않는다.
- 계약: 토스 상점의 자동결제 계약·승인과 상점별 테스트키·운영키를 확인한다. 개발자 테스트 상점의 성공을 운영 상점 승인으로 취급하지 않는다. 최종 상점에서 카드 등록, 최초 승인, 월 갱신, 해지/재개, 카드 교체, 전액 취소/조회와 응답 유실 시나리오를 반복한다.
- 위탁/국외 처리: 실제 Resend 요금제·보존 계약, 현재 Cloudflare Pages 호스팅과 롤백용 Vercel의 로그 보존 및 처리 지역/수탁 조건을 확인한 뒤 개인정보처리방침을 맞춘다. 표준 공개 정책과 개별 계약을 구분한다. 변경되는 조건에 따라 필요한 안내·동의를 적용한다.
- 광고: AdSense 사이트 승인, 광고 단위, ads.txt, 광고 게재 설정과 공개 고지를 확인한다. 운영 origin에서 허용·거부·철회, 지역별 Google CMP와 기존 광고 제거 회원의 0 요청을 확인한다. Google 동의 결과 불명은 광고를 보내지 않는다.
- 키: 실키와 32바이트 암호화키는 서버 전용 설정에 둔다. 암호화키 복구 사본을 접근 제한하여 보존한다. 암호화키를 회전하려면 기존 참조 재암호화가 먼저 필요하다. 공개 번들/PR/로그에는 넣지 않는다.

## 정상 운영

매일 `Billing result unknown`, `Billing refund pending`, `Billing key cleanup pending` 경고 및 해당 원장과 PG 주문을 대조한다. 자동 FutureCall 5분 주기는 사람의 장애 점검을 대체하지 않는다. 동일 주문의 결과가 불명인 동안 새 주문으로 다시 청구하지 않는다. 장애 시 신규 판매 중단과 기존 주문 대사/환불 처리를 구분하여 진행한다. `ALFINDER_BILLING_CHARGES_PAUSED=true`로 신규·갱신 청구를 중단하되 기존 주문 조회·대기 환불·키 삭제를 계속한다. LIVE_ENABLED=false는 provider worker도 멈추므로 기존 거래 처리용 중단 설정과 혼동하지 않는다. 현재 paid 기간의 공급자 직접 전액 취소는 5분마다 동일 주문 GET으로 대사한다. 조회 실패는 권한을 임의로 환불 처리하지 않고 안전한 원장 ID 경고를 남긴다.

문의 환불은 `monetization-launch-readiness.md`의 관리자 절차를 사용한다. 문의에 카드번호/비밀번호/신분증을 요구하지 않는다. 화면의 '확인 중'은 완료가 아니다. 카드사 입금 반영과 PG 취소 확인을 구분한다.

## 기록 보존과 파기

계약/철회와 결제/공급 기록은 5년, 소비자 불만/분쟁 처리 기록은 3년, 표시/광고 거래 기록은 6개월 보존 대상이다. 탈퇴와 법정 거래 기록 파기는 별개다. 탈퇴 계정과 거래 기록을 광고·일반 회원 기능에 재사용하지 않는다. 법정 기간 만료 및 분쟁·조사 보존 필요 여부를 확인한 후 파기한다.

월 단위로 다음 목록을 접근 제한한 운영 기록에 남긴다: 보관 범주, 기준 거래/처리 종료일, 적용 기간, 만료일, 계속 보관 사유, 담당 확인일, 실제 파기일. 현재 결제 모델의 이용 기간/약관 동의와 PG 취소 확인 기록을 함께 대조한다. 원장 5년 만료 시 자동 파기는 아직 없으므로 임의로 SQL 삭제하거나 외래키를 제거하지 않는다. 최초 만료 전 파기 실행기와 dry-run 목록, 분쟁 보존 예외, 관련 테이블 및 백업 영향 검증을 완료해야 한다.

운영 정기 백업은 최근 정상 완료 사본 3개를 순환한다. 이전 마이그레이션 스냅샷은 별도 목록으로 관리하고 필요한 복구/보존 범위를 확인한 후 정리한다. 정상 백업/복구 검증 전에 마지막 복구 사본을 지우지 않는다. 이메일 문의 사본과 Resend/Cloudflare/Vercel 제공자 보존도 별도로 확인한다. 실행 완료와 계획을 구분하여 기록한다.
