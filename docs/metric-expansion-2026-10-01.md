사업부문 비중은 금액/비중으로 역산한 공통 분모 구간이 겹치는지 확인한다(소수 첫째 자리 반올림 ±0.05%p). 내부거래 제거 때문에 부문 매출 합계를 회사 전체 매출로 강제하지 않는다. 금액·비중 두 줄 머리글과 2~3기 비교표만 지원한다. 여러 표가 동일 항목으로 충돌하면 표 전체를 제외한다. 따라서 모든 공시 형식을 포괄하는 추출은 아니다.

새 `DocumentFactKind` 3개는 기존 enum 끝에 추가했다. 테이블/컬럼 변경은 없고 Serverpod 자동 생성 코드를 사용했다. 기존 `ProductionFacts.store`의 트랜잭션·출처·관리자 재추출 경로를 재사용한다.

## 과거 배수의 한계

시세일 **이전**에 접수된 보관 공시만 분모에 사용하고 정정 공시를 과거로 소급하지 않는다. 현재 `summary`에 남은 최신 정정 보고서를 이용하므로 정정 전 보고서를 모두 복원한 시점별 데이터는 아니다. 공시 누락은 결측으로 남기거나 그 전에 확보된 보고서만 사용한다. 18개월을 넘은 재무는 사용하지 않는다. 동일 날짜 접수 건은 장중/장후를 알 수 없어 제외한다.

시총은 수집된 회사 종목을 기준으로 한다. 한번 관측한 종목은 이후에도 요구하므로 종목이 사라지면 시총을 작게 계산하지 않고 결측 처리한다. 정확한 상장·상장폐지 이력이 연결되기 전에는 종목 구성 완전성을 보장하지 않는다. 월별 마지막 **수집** 거래일이며 월 전체가 미수집된 경우 달력 말일을 결측 자리로 유지하며, 이 자리에는 실제 시세값을 넣지 않는다.

이는 월별 배수와 관측 범위다. 미래 실적 컨센서스, 목표주가 또는 배수별 이론 주가 밴드를 추가했다고 주장하지 않는다.

## 검증 및 현재 적용 상태

- 서버 테스트 49개: 새 파서·손실·열 순서·중복 표, 종목 누락, 공개 엔드포인트 및 출처, 기존 매출·생산 파서, 생성 코드 등록, 격리 DB 통합 테스트 통과.
- Flutter 테스트 34개: 계산식·공시일·손실·FCF·단위/문서 불일치, 320/1280px 기간 선택과 원문 펼침, 기존 재무/디자인 경계 테스트 통과.
- 실제 저장 삼성전자 FY2025 본문: 지역 매출 5개 + 부문 매출/이익 8개 추출. 삼성SDS: 지역 5개 + 부문 매출/이익 4개. 모든 evidence가 입력 원문의 부분 문자열임을 확인. 전 기업 추출률/정확도 전수 검증은 하지 않았다.
- 실제 공개 `market.companyCapHistory` 호출: 삼성전자 보통주·우선주 합산과 출처 반환 확인.
- 로컬 브라우저 삼성전자 재무 탭: PER 3년, P/FCF, 1년 전환, 월별 계산 근거 펼침 확인. 읽기 전용 기능이므로 DB 재추출 없이 작동한다.
- Flutter 전체 분석 이상 없음. 서버 전체 분석에 이번 변경 밖 `semiconductor_activity_rules.dart`의 중괄호 스타일 info 1개가 관측되었으며 오류는 없었다.

**Mac 운영 DB는 iwinv 이전을 위해 읽기 전용으로 동결된 상태다.** 동결을 해제하거나 운영 DB에 쓰지 않았다. 사업부문/지역 화면은 구현·테스트 완료, 운영 데이터 재추출과 운영 배포는 미완료다.

이전 완료 후 쓰기 가능한 서버에 코드를 반영하고, 인증된 관리자 세션에서 `ingest.rebuildProductionFacts(corpCode: ...)`로 대상 기업을 먼저 검증한다. 이후 전체 오프라인 재추출과 데이터 커버리지 점검을 진행한다. 인증을 우회하지 않는다. 재현용 읽기 전용 도구:

```sh
cd investment_ontology_serverpod_server
dart run tool/audit_business_breakdowns.dart /path/to/business-content.txt 2025
```
