# 공시 주요정보 외 수집 범위

사용자 요청(2026-10-02): 공시 주요정보 28종을 제외한 수집을 우선 마무리한다. 범위는 종목코드가 있는 기업 기본정보, 최종 정정 기준 연간 5개년 재무·사업 본문 및 연간 이후 최신 중간보고서, 최근 5년 시세·지수다. 범위 밖 장부와 저장 자료는 삭제하거나 완료로 바꾸지 않는다.

사업 본문은 `business_documents` 관리자 작업으로 분리했다. 실제 본문과 같은 기업·기간·접수번호를 검증하며 빈 응답을 완료로 세지 않는다. 명시적인 첨부 정정만 같은 기간 이전 원본을 재사용한다. 28종 작업은 본문 작업이 예약·실행 중이면 실행 순서를 양보하고 재개한다. 한 실행당 최대 200건, 20건마다 진척 저장, 정상 미완료 30초 뒤 재개, 공개 요청 6회 연속 실패 시 15분 뒤 재개를 적용한다. 본문 전용 작업은 전체 공유 일일 한도 안에서 19,900회까지 활용하고 100회는 기업 기본정보 등에 남긴다. 일반 28종 작업의 예산과 원천 요청 지연은 유지한다. 첨부정정의 이전 접수 탐색이 API 예산을 기다리는 경우 해당 본문만 대기시키고 다른 공개 본문을 계속 받는다. 남은 항목이 모두 확인된 API 대기이면 다음 KST 자정 뒤 재개해 빈 작업을 반복하지 않는다.

재무의 내부 사업연도는 결산연도이고, DART 재무 조회 연도는 보고서 기간 말의 달력연도다. 비12월 결산 중간보고서에서는 두 값이 다를 수 있다. [공식 공개 재무 조회](https://opendart.fss.or.kr/disclosureinfo/fnltt/singl/main.do)의 기준과 실제 최신 접수번호를 대조한다. API 응답의 기업·조회 연도·코드 및 실제 접수번호의 기간을 검증하고, 다른 기간을 내부 사업연도로 재라벨하지 않는다.

이미 잘못된 조회 연도로 빈 응답을 받은 최신 중간보고서만 1회 재시도한다. 일반 재무 백필의 19,000회 예산은 유지하고 이 오류 복구는 하루 전체 20,000회 안의 잔여 호출에서 한 실행당 최대 40회만 사용한다. 매 기준별 복구 호출 전 합산 사용량을 확인한다. 기타 빈 응답을 광범위하게 초기화하지 않는다.

연간 API 기간 불일치는 정확한 접수번호의 공개 DART XBRL에서 기업·기간·연결/별도·KRW 단위·정밀도를 검증해 핵심 계정만 복구한다. 원문 URL과 SHA256을 Source에 남기고 전체 재무제표 복구로 표시하지 않는다. 공개 원본 복구에는 API 키를 사용하지 않는다.

기업개황 부분 실패는 실패 상태와 변경분 재시도 예약을 남긴다. 시세 최근 빈 응답은 휴장이나 미게시로 단정하지 않고 실제 장부 없는 날짜로 남긴다. 데이터 화면은 실제 저장, API 자료 없음, 대기, 실패 및 최근 미확보 날짜를 구분한다.


## 실제 기간과 원접수 출처의 저장 여부

재무 장부의 `stored`만으로 보고서 확보를 판정하지 않는다. 같은 사업연도에 여러 결산월이 있는 기업은 다른 기간의 API 응답이 저장될 수 있다. 데이터 페이지의 저장 건수는 실제 결산월이 일치하는 보고서, 그 원접수 출처, 해당 출처에 속한 숫자가 모두 연결되어 있어야 포함한다. 원접수 장부가 빠지거나 결산월이 다른 `stored` 항목은 미완료로 표시하며 다른 기간의 숫자를 재라벨하지 않는다.

2026-10-02 추가 원천 감사에서 기존 장부의 저장 14,632건 중 57기간은 실제 결산월 자료가 없고, 191기간은 숫자의 원접수 장부 연결이 빠져 있었다. 추가로 선진 2024.12와 코스나인 2025.12는 보고서와 출처가 있지만 당기 금액이 전부 비어 있어 저장 완료에서 제외한다. 새 조건을 운영 DB에 읽기전용 적용한 결과 15,288기간 중 저장 14,382, 출처·당기값 미확보 250, API 양 기준 자료 없음 656이었다. 집계 조회는 663ms였다. 이 수치는 감사 시점의 스냅샷이다. 191기간(연간 188, 최신 반기 3)은 공식 표지로 회사코드·보고서 종류·실제 결산기간이 맞는 후보를 확인했으며, 원접수 메타데이터 복구는 실행 시 공식 회사코드·표지 기간·원접수 문서 좌표를 다시 확인하고, 요청한 정정 공시와 다른 접수번호이면 공식 보고서 선택 목록의 명시 연결도 확인한다. 검증 후 원접수 장부와 URL·SHA 감사 기록만 추가하며 기존 숫자와 Source ID를 보존한다. 정상 잔여 후보는 20건 단위로 양보해 이어받고, 통신·명시 연결 실패는 부분 계정으로 대체하지 않는다. 화면의 기간 일치 저장 집계는 숫자와 원접수 기간의 가용성이다. 이는 모든 숫자나 모든 정정 변경사항의 재검증을 뜻하지 않는다. 실제 기간이 빠진 57기간은 정확한 원문으로 따로 복구한다.

재무 API 양 기준 자료 없음 656기간도 전체 재무제표가 없다는 뜻으로 해석하지 않는다. 원문에 숫자가 있는지 별도 확인해야 하며, 원문 취득·검증이 끝나지 않은 항목을 수집 완료라고 부르지 않는다.

공식 원접수 연결 누락 191기간은 전체 대상의 본문 선택 목록(`id=family`)에서도 원접수 연결을 확인했다. 공시 이력 목록에 같은 접수번호가 중복 표시되므로 전역 option 개수로 모호함을 판정하지 않는다. 실제 연간·반기 원문을 고정한 회귀 테스트로 해당 경계를 검증한다. 당기 금액이 전부 빈 기존 보고서는 비교기간 숫자와 Source를 보존한 채 미확보로 남기며, 기존 보고서 존재만으로 재수집 성공을 반환하지 않는다.
